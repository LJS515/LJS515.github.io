机器人与具身智能全栈开发路线图：从数学基础到机器人学习与全身控制

具身智能机器人不是单一算法问题。

真正做系统时，它会同时牵涉：

  • 机械结构
  • 电机与驱动器
  • 传感器
  • 坐标系
  • 运动学
  • 动力学
  • 状态估计
  • 控制器
  • 仿真
  • 感知模型
  • 接触与抓取

如果学习路线没有层级，很容易出现一个问题：

上层概念看了很多，底层闭环却跑不起来。

这篇文章作为本系列的路线图，不展开具体公式推导，而是梳理工程依赖关系：

先学什么，为什么学，学到什么程度，下一层会接到哪里。

读这篇时，可以先把它当成一张总地图。后面每一篇文章都会沿着这条线往下走：从数学和坐标系开始，逐步进入运动学、滤波、机械臂控制、接触抓取、四足控制、人形平衡、全身控制和状态估计。

一、总目标：做能真正工作的机器人系统

这个系列的目标不是写一组泛泛的 AI 概念文章，而是面向真实机器人全栈开发。

目标机器人包括：

  • 机械臂
  • 四足机器人
  • 人形/双足机器人
  • 灵巧手
  • 带视觉、触觉和语言模型的具身操作系统

核心判断很简单：

没有底层可控的身体，上层智能很难落地。

所以这条路线会优先建立：

  1. 数学骨架
  2. 空间与运动表示
  3. 状态估计
  4. 控制闭环
  5. 接触与操作
  6. 人形全身控制

二、第一层：数学基础

对应文章：

  • 具身智能中的数学基础

这一层解决的问题是：

机器人系统里最常用的数学工具是什么。

重点不是追求纯数学证明，而是建立工程可用的工具箱：

  • 线性代数
  • 微积分
  • 概率统计
  • 三维几何
  • 运动学
  • 动力学
  • 控制与优化

这一层至少要学到：

  • 能看懂坐标变换
  • 能理解速度、加速度、力矩
  • 能知道为什么传感器有噪声
  • 能把公式写进代码
  • 能意识到数值条件、单位和坐标系一致性的重要性

这一层没打稳，后面的运动学、滤波、QP、全身控制都会变成“看起来会，调起来乱”。

三、第二层：空间表示

对应文章：

  • 具身智能中的坐标系、旋转矩阵与四元数

这一层解决的问题是：

机器人如何描述三维空间。

机器人系统里最常见的错误之一，就是坐标系错了。

这会导致：

  • 机械臂抓偏
  • 相机识别结果转到基座坐标后出错
  • IMU 姿态方向反了
  • 四足足端落点偏移
  • 人形支撑脚和骨盆关系不一致

这一层至少要掌握：

  • 世界坐标系、机身坐标系、相机坐标系、末端坐标系
  • 旋转矩阵
  • 欧拉角
  • 四元数
  • 齐次变换矩阵
  • 坐标变换方向和矩阵连乘顺序

工程标准不是“知道这些名词”，而是：

能够在代码里稳定地维护坐标链。

四、第三层：运动学

对应文章：

  • 机器人运动学入门：从二连杆到六轴机械臂

这一层解决的问题是：

关节怎么决定末端，末端目标又如何反推关节。

重点包括：

  • 正运动学
  • 逆运动学
  • 工作空间
  • DH 参数
  • 雅可比矩阵
  • 奇异点
  • 数值逆解

机械臂、四足腿、人形腿、灵巧手指，本质上都离不开运动链建模。

这一层要达到的工程能力是：

  • 能写二连杆正逆解
  • 能看懂六轴机械臂运动链
  • 能用雅可比理解速度映射
  • 能判断逆解无解、多解和奇异点问题
  • 能把末端任务转换成关节任务

运动学解决的是：

几何上能不能到。

但它不解决：

能不能稳、能不能抗扰、能不能接触。

这些需要下一层。

五、第四层：概率、滤波与状态估计

对应文章：

  • 具身智能中的概率与滤波：IMU、编码器和卡尔曼滤波
  • 人形机器人中的状态估计：IMU、足底接触与浮动基状态恢复

这一层解决的问题是：

机器人如何知道自己当前处于什么状态。

真实硬件不会直接给你“真值”。

你拿到的是：

  • 带噪声的 IMU
  • 带量化误差的编码器
  • 带延迟的视觉
  • 带阈值误判的接触信号

所以必须做状态估计。

基础阶段要理解：

  • 噪声
  • 偏置
  • 协方差
  • 卡尔曼滤波
  • 互补滤波
  • IMU 和编码器融合

人形阶段要进一步理解：

  • 浮动基状态
  • 足底接触约束
  • 单支撑与双支撑对估计的影响
  • 估计链和全身控制的闭环关系

这一层非常关键，因为很多所谓控制问题，本质上是：

控制器拿到了错误状态。

六、第五层：感知与三维理解（视觉 / SLAM / 3D）

本节是对“状态估计”的横向补充：状态估计回答“我现在的位姿与速度是什么”，感知回答“周围有什么、在哪、能不能抓”。两者通过同一条坐标链交付给控制器与规划器。系列内已经有单独文章《具身智能中的感知与三维理解：相机、SLAM 与 3D 表示》展开。

对应文章：

  • 具身智能中的感知与三维理解：相机、SLAM 与 3D 表示

这一层解决的问题是：

机器人如何把原始传感器信号变成对世界的几何与语义理解。

这一层涉及的话题包括：

  • 相机模型与标定（针孔、鱼眼、双目、深度相机）
  • 手眼标定与 IMU-相机外参标定
  • 视觉里程计与视觉惯性里程计（VO / VIO）
  • 视觉 SLAM、激光 SLAM 与视惯-激光融合
  • 3D 表示：点云、深度图、TSDF、NeRF、3D Gaussian Splatting
  • 检测、分割、6D 位姿估计
  • 触觉与力觉感知
  • 多传感器时间戳同步与坐标链管理

工程能力目标是：

  • 能稳定标定单目 / 双目 / IMU-相机这一类组合
  • 能跑通一个开源 SLAM 系统，并把输出接到 TF 与状态估计节点
  • 能从点云或 RGB-D 图像里抽出可抓取目标
  • 能分辨一次失败是“感知偏了”、“标定漂了”还是“控制超调了”

推荐并行实践的开源项目（按用法分组）：

  • SLAM / VIO：ORB-SLAM3、VINS-Fusion（HKUST）、FAST-LIO2、LIO-SAM、Kimera（MIT）
  • 3D 表示与重建：Open3D、COLMAP、nerfstudio、gsplat
  • 通用视觉与标定：OpenCV、Kalibr（ETH ASL）、AprilTag
  • 开放词汇感知：SAM 2、Grounding DINO、CLIP——把“指物即抓”接入感知层
  • 触觉：GelSight 系列开源驱动、DIGIT

这些项目都能在仿真和真机上跑出可观察的结果，是简历上“做过完整感知闭环”的天然抓手。

这一层一旦打通，后面机械臂、四足和人形系统才能从“会动”进入“在真实世界里完成任务”。

七、第六层：机械臂控制

对应文章：

  • 机械臂控制基础：轨迹规划、PID 与末端控制

这一层解决的问题是：

运动学解出来以后，机械臂如何稳定、平滑、可重复地执行。

重点包括：

  • 关节控制
  • 末端控制
  • 轨迹规划
  • PID
  • 前馈控制
  • 重力补偿
  • 阻抗控制
  • 控制频率与带宽
  • 接触模式切换

机械臂控制里一个重要判断是：

能到目标点，不等于控制做好了。

真正的控制能力体现在：

  • 轨迹过程是否平滑
  • 到位是否稳定
  • 负载变化是否可控
  • 接触任务是否柔顺
  • 仿真到真机是否不过激

这一层是后续抓取、装配、灵巧操作的基础。

八、第七层：接触与抓取

对应文章：

  • 具身智能中的接触与抓取：从机械臂到灵巧手

这一层解决的问题是：

机器人如何从“能动”进入“能操作世界”。

接触与抓取不是简单夹一下。

完整流程包括：

  • 目标识别
  • 位姿估计
  • 抓取位姿选择
  • 接近路径规划
  • 接触建立
  • 抓取保持
  • 搬运
  • 释放

这一层需要掌握：

  • 接触点
  • 接触法向
  • 摩擦
  • 抓取稳定性
  • 两指夹爪和灵巧手的差异
  • 触觉与滑移检测
  • 接触模式切换

抓取失败不能只怪夹爪。

真正排查时必须按链路看：

感知、标定、路径、接触、夹持力、搬运过程。

九、第八层：四足控制

对应文章：

  • 四足机器人控制基础：足端轨迹、质心与稳定性

这一层解决的问题是：

机器人如何在接触切换中稳定移动。

重点包括：

  • 支撑相
  • 摆动相
  • 步态
  • 足端轨迹
  • 落脚点
  • 质心
  • 支撑多边形
  • 动态稳定
  • 接触力分配
  • QP / MPC 的进入点

四足控制的核心不是让四条腿各自摆动，而是：

让机身、足端、接触和时间节奏形成稳定闭环。

这一层能很好地把运动学、状态估计和控制串起来。

十、第九层：人形机器人控制

对应文章：

  • 人形机器人控制基础：质心、ZMP 与步态
  • 人形机器人全身控制：任务、约束与 QP
  • 人形机器人中的全身控制实现：从动力学方程到 QP 求解
  • 人形机器人中的接触力分配与支撑约束
  • 人形机器人中的状态估计：IMU、足底接触与浮动基状态恢复

这一层解决的问题是：

机器人如何在高自由度、多接触、低稳定裕度下完成平衡、行走和操作。

这条线目前分成五个子主题：

10.1 质心、ZMP 与步态

建立人形平衡的基础直觉：

  • 双支撑
  • 单支撑
  • 质心
  • ZMP
  • LIPM
  • Capture Point
  • 落脚点

10.2 全身控制框架

理解为什么人形不能只做关节控制或末端控制，而必须统一处理：

  • 任务
  • 约束
  • 接触
  • 冗余
  • 优先级

10.3 从动力学方程到 QP

把全身控制落到实现骨架：

  • 浮动基动力学
  • 广义坐标
  • 接触雅可比
  • 优化变量
  • 任务代价项
  • 摩擦与力矩约束

10.4 接触力分配与支撑约束

理解人形为什么不是“脚踩地就稳”，而是要维持：

  • 法向力非负
  • 摩擦约束满足
  • 支撑力连续转移
  • 压力中心不过边界

10.5 状态估计闭环

理解控制器依赖的状态从哪里来：

  • IMU
  • 编码器
  • 足底接触
  • 浮动基状态恢复
  • 接触可信度判断

人形这条线的核心结论是：

人形不是靠某一个步态模板走起来的，而是靠状态估计、接触约束、全身控制和支撑力分配持续闭环。

十一、第十层：仿真平台——从 URDF 到 GPU 并行训练

仿真不属于某一层，而是贯穿所有层。控制器调试、状态估计验证、强化学习训练、视觉数据生成、Sim2Real 评估都发生在仿真里。建议从运动学学完那一刻起就开始接触仿真，越往后越离不开它。

这一层解决的问题是：

机器人开发如何在真机不可控、不可用、不可重复时保持快速迭代。

主流仿真器各有侧重，按用途选型：

  • MuJoCo：接触建模和连续动力学口碑最稳，2022 起开源，几乎是机器人 RL/控制研究的事实标准
  • NVIDIA Isaac Sim / Isaac Lab：GPU 并行（数千环境）训练腿式与操作策略的主力栈
  • Genesis：2024 末开源的高速并行仿真框架，主打训练速度，社区上升期
  • Gazebo（gz-sim）：ROS 生态原生仿真，硬件接口与传感器模型最完整
  • PyBullet：入门门槛最低，API 友好，适合机械臂和抓取早期实验
  • SAPIEN：UCSD 系，操作类研究常用，Articulation 关节件处理细致
  • Drake：MIT/TRI 维护，把物理仿真、轨迹优化与接触建模放在同一框架
  • Webots：教学场景常用，开箱即用机器人模型多
  • Habitat 2.0 / 3.0：Meta 出品，主打具身导航与人居场景

资产格式与建模工具也是这一层的必修：

  • URDF / MJCF / USD：机械描述格式，分别对应 ROS、MuJoCo、Isaac 生态
  • mujoco_menagerie：DeepMind 维护的高质量机器人模型库，Go2、H1、Allegro 等都有官方版
  • OnShape-to-Robot、urdf-loaders：URDF 导出与可视化调试链

工程能力目标：

  • 能把一台真机的 URDF / MJCF 跑起来并对齐 TF 链
  • 能用 MuJoCo 或 PyBullet 写一个最小的机械臂 / 四足控制 demo
  • 能在 Isaac Lab 或 legged_gym 里跑通一次步态策略训练，理解并行环境的吞吐量
  • 能判断仿真是因为”建模偏了”、”接触参数错了”还是”控制器逻辑错了”才输出怪结果

推荐并行实践的开源项目：

  • 资产 / 模型：mujoco_menagerie、Isaac Lab assets、Unitree 官方 URDF
  • 腿式 RL 训练：legged_gym（ETH/RSL）、Humanoid-Gym、Isaac Lab、OmniIsaacGymEnvs
  • 操作类基线：ManiSkill2/3（SAPIEN）、robosuite（UT Austin）
  • 轨迹优化 / 接触建模：Drake、Crocoddyl
  • 训练后端：rsl_rl、rl_games、Stable-Baselines3、CleanRL

Sim2Real 是这一层留给下一层（机器人学习）的接口，至少要了解：

  • 域随机化（Domain Randomization）
  • 系统辨识（System Identification）
  • 在线适配（RMA、Adaptation Modules）
  • 评估指标：真机零样本成功率、相对仿真奖励的退化幅度

仿真栈做扎实，简历上才能讲清楚”训练—部署—回归”这一整条闭环，而不是只列一句”会用 MuJoCo”。

十二、第十一层：中间件——ROS 2、DDS 与机器人系统工程

这一层不教算法，教”如何让算法在一台真机上稳定跑起来”。ROS 2 是当前事实标准的机器人中间件，但工程化绕不开 DDS、launch、参数、TF、bag 录制回放、实时性这一整套基础设施。

这一层解决的问题是：

怎么把感知、控制、状态估计和上层任务这些模块，组织成一个能调试、能复现、能上真机的系统。

ROS 2 需要建立的基础认知：

  • 节点、话题、服务、动作（Action）
  • QoS：可靠性、历史深度、deadline，跟丢包和时序错位高度相关
  • TF2：坐标链管理；它要和状态估计、SLAM、感知全部打通
  • launch（Python）、参数声明、生命周期节点
  • rosbag2：数据回放是机器人调试最重要的工具之一
  • 实时性：ros2_control 控制环、Preempt-RT 内核与延迟测量

ROS 1 vs ROS 2：

  • 新项目几乎默认 ROS 2（Humble / Iron / Jazzy）
  • ROS 1 还会在老项目和部分工业系统里出现，理解 catkin / roscpp 仍有价值
  • 国内还会接触 CyberRT（百度 Apollo）、RT-Thread、AGV 厂家私有总线，但接口理念大同小异

工程能力目标：

  • 能写一个 C++ / Python 节点，订阅传感器、发布控制
  • 能写 launch 文件、配置参数，组织一个 ros2_control 控制器
  • 能录制 rosbag2 并回放调试一次偶发问题
  • 能配合 Foxglove 或 rerun 做可视化与日志追踪

推荐并行实践的开源项目：

  • 导航与规划：Nav2、MoveIt 2、OMPL
  • 控制框架：ros2_control、controller_manager、SimpleFOC（驱动器端）
  • 嵌入式接入：micro-ROS（MCU 上的 ROS 2 客户端）
  • NVIDIA 集成：Isaac ROS（GPU 加速感知节点）
  • 可视化与日志：Foxglove Studio、rerun.io、PlotJuggler、RViz2
  • 桥接通信：rosbridge_suite、zenoh-bridge-ros2

机器人项目看上去是控制和学习问题，但 80% 的开发时间花在中间件、调参、节点编排和坐标链维护上。这一层练扎实，简历上能直接体现工程化能力，也是和纯算法岗位拉开差距的部分。

十三、第十二层：机器人学习——强化学习、模仿学习与 VLA

经典控制走到一定程度，会有两类问题始终绕不开：高维接触下手工建模代价高、跨任务跨本体迁移难。机器人学习就是把数据驱动的方法（RL / IL / 大模型策略）接到这条工程链路上，但它不是经典控制的替代，而是上层补充——底层稳态闭环依然由前面几层提供。

这一层解决的问题是：

机器人如何从数据中学策略，并在仿真到真机的迁移中保持可靠性。

子主题按依赖分四组：

A. 强化学习基础

  • 价值与策略迭代、TD(0)、PPO、SAC、DDPG/TD3
  • 在线 vs 离线 RL、actor-critic、熵正则、GAE
  • 奖励设计陷阱：sparse vs shaping、奖励 hacking、终止条件
  • 多智能体与层次化 RL（HRL）

并行项目：

  • Stable-Baselines3 — 教学级 RL 实现，搭一个 PPO baseline 最快
  • CleanRL — 单文件实现，研究复现最适合
  • Spinning Up（OpenAI） — 入门教材级仓库
  • Tianshou、skrl — 工程化更强的国产 / 开源训练框架

B. 机器人 RL 训练栈（GPU 并行）

把 S4 的仿真栈接到 PPO/SAC，规模化训练腿式 / 操作策略。

  • legged_gym（ETH RSL） — 四足/人形并行训练的源头
  • Humanoid-Gym（清华团队） — 在 legged_gym 之上把人形跑通
  • Isaac Lab — NVIDIA 现役主力，整合 legged_gym 一脉
  • rsl_rl、rl_games、OmniIsaacGymEnvs — 配套训练后端

C. 模仿学习与数据驱动操作

近两年最火的一条线：用人类示教 + 大模型把”灵巧操作”做出来。

  • Diffusion Policy（Columbia） — 把扩散模型用作动作分布的成熟基线
  • ACT / ALOHA（Stanford） — Action Chunking Transformer，双臂遥操数据
  • Mobile ALOHA / HumanPlus（Stanford 2024） — 移动操作与人形示教
  • Robomimic — 操作类模仿学习的标准评测套件
  • LeRobot（HuggingFace） — 端到端机器人学习工具链，含 So-100 低成本教学臂

D. 视觉-语言-动作（VLA）与世界模型

机器人学习的”前沿前线”。这一段更新最快，应该按季度复核。

  • OpenVLA（Stanford / 2024） — 开源 7B VLA 基线
  • Octo（Berkeley / 2024） — 通用机器人策略 transformer
  • pi0（Physical Intelligence / 2024 Q4） — 业界关注度极高的 VLA 模型
  • RT-2 / RT-X（Google / 2023） — VLA 起点与 Open X-Embodiment 数据集
  • DreamerV3 / TD-MPC2 — 世界模型 + 模型预测控制的代表
  • Genie / GAIA-1 — 世界模型方向的视频生成式基线

Sim2Real 是这一层的工程门槛：

  • 域随机化（DR）、系统辨识（SysID）
  • 在线适配（RMA、AdaptNet）
  • 真机零样本评估、回放数据集校验、影子模式上线

工程能力目标：

  • 能跑通一个 PPO 在 Isaac Lab / legged_gym 里的腿式步态训练，并把策略部署到仿真真机回环
  • 能复现 Diffusion Policy 或 ACT 的一个操作任务（哪怕是夹爪堆方块）
  • 能读懂一篇 VLA 论文的训练数据来源、网络结构与评估方式
  • 能解释”为什么仿真很高分但真机掉到 30%”——并知道至少两条排查方向

简历视角：这一层做出可演示的策略 + 一段真机视频，比刷十篇论文更直接。
保持对 LeRobot、Isaac Lab、pi0 这类活跃项目的跟进，是这条赛道最便宜的杠杆。

十四、第十三层：硬件与系统集成——电机、传感器、总线与整机平台

算法栈做得再漂亮，最终都要落到一台真机上。这一层不会写在每天的代码里，但它决定了上面几层能不能跑——电流环带宽不够，全身 QP 也救不回来；总线延迟不可控，状态估计闭环就会震荡。

这一层解决的问题是：

怎么让一台机器人在物理上具备”被算法可靠控制”的能力。

需要建立基础认知的硬件子主题：

  • 执行器：BLDC + FOC、谐波减速、行星减速、QDD（准直驱）、串联弹性 SEA
  • 驱动器：电流环、力矩控制、温度保护、PDO 周期与控制周期对齐
  • 编码器：增量 vs 绝对、单圈 vs 多圈、磁编 vs 光编、电气零位标定
  • IMU 与 F/T 传感器：噪声密度、bias 漂移、安装振动耦合、量程
  • 触觉：力/力矩、滑移检测、视触觉（GelSight / DIGIT 系）
  • 通讯总线：EtherCAT、CAN / CAN-FD、RS485、EtherNet/IP、私有总线
  • 嵌入式与实时性：STM32 / ESP32、RTOS、Preempt-RT、cyclictest 测延迟
  • 电源：电池规格选型、BMS、隔离与稳压、共地与抗干扰
  • 结构与机械：刚度、间隙、热设计、紧急停机回路（E-Stop）

工程能力目标：

  • 能读懂一份电机数据手册，并把它和控制带宽、负载惯量对应起来
  • 能用 ODrive / SimpleFOC / 自研驱动跑通一只电机的速度 + 力矩控制
  • 能基于 EtherCAT 主站把 6-8 只电机串成一条控制环
  • 能用 cyclictest 量化系统抖动，并理解什么样的抖动会让控制器失稳
  • 能定位”控制器无故震荡”是因为驱动器、总线、机械还是软件

推荐并行实践的开源项目与参考平台：

  • 驱动器与电机控制：ODrive、SimpleFOC、MIT Mini Cheetah Motor Driver、moteus（mjbots）
  • EtherCAT / 实时：SOEM、IgH EtherCAT Master、ros2_control + Preempt-RT
  • 嵌入式接入：micro-ROS、FreeRTOS、Zephyr、RT-Thread
  • 开源整机平台：
    • Solo / ODRI（Open Dynamic Robot Initiative） — 四足 + 双足开源参考
    • MIT Mini Cheetah 复刻线 — 四足 QDD 教科书级参考
    • MIT Humanoid — 早期开源人形参考
    • LeapHand（CMU） — 低成本灵巧手开源方案
    • SO-100 / Koch arm（LeRobot 生态） — 低成本机械臂，配遥操数据采集
  • 商用整机（按 2024-2025 公开信息整理）：
    • 四足：Unitree Go2 / B2、ANYmal、Spot、宇树 Aliengo 系
    • 人形：Unitree H1 / G1、Booster T1、Fourier GR-1、Apptronik Apollo、Figure 02、1X NEO、Tesla Optimus、Sanctuary Phoenix
    • 机械臂：Franka Research 3、UR 系列、AUBO、JAKA、富士 CRX

简历视角：硬件链路是大多数算法岗位拉不开的地方，但它是工程岗与硬件岗最直接的差异化资产。能写”用 SOEM 把一条 EtherCAT 串到 1kHz 控制环”或”基于 ODrive 自调 FOC 实现 5A 力矩控制”，比泛泛写”熟悉机器人系统”有效得多。

十五、第十四层：部署、安全与产品化——从能跑到能交付

这一层是被低估最多的部分。研究演示和真正交付一台机器人之间的差距，大多数发生在这里：策略导出、边缘推理、安全包络、影子上线、监控回流。

这一层解决的问题是：

怎么让一个在仿真和实验室里跑通的方案，稳定运行在真机上、并能被持续迭代。

需要建立的子主题：

  • 模型导出与推理加速：PyTorch -> ONNX -> TensorRT / OpenVINO / TVM，量化（FP16 / INT8）、算子兼容
  • 边缘平台：Jetson Orin / Thor、RK3588、地平线 J5 / J6、寒武纪、华为 Atlas
  • 实时与延迟：策略推理延迟、控制环抖动、感知到动作端到端时延
  • 安全包络：碰撞检测、力矩 / 速度限幅、关节极限、双层 E-Stop、Cat-3 / SIL-2 概念
  • 影子模式与灰度：策略不接管但在线评估、A/B 发布、回退路径
  • 数据闭环：真机轨迹回流、失败案例打标、再训练
  • 监控：在线指标、异常检测、日志聚合、长跑稳定性

工程能力目标：

  • 能把一个 PyTorch 策略导出 ONNX 并在 Jetson Orin 上做到目标推理频率
  • 能设计一份”安全包络”清单：哪些异常必须立即停机、哪些只需降级
  • 能定义一个”上线门槛”——而不是”演示效果好就发”
  • 能搭一条最小数据闭环：真机日志 -> 标注 -> 再训练 -> 影子模式回归

推荐并行实践的开源项目：

  • 推理运行时：ONNX Runtime、TensorRT、OpenVINO、TVM、TFLite、MNN
  • 边缘加速参考：NVIDIA Jetson Inference、Isaac ROS、TensorRT-LLM（若用 VLA）
  • 可观测性：Prometheus + Grafana、Loki、OpenTelemetry
  • 数据 / 日志：rosbag2、Foxglove Data Platform、rerun.io
  • MLOps 侧：MLflow、Weights & Biases、DVC（数据集版本）

简历视角：能讲清楚一条”训练 -> 导出 -> 部署 -> 上线监控 -> 回流再训练”完整链路的人非常稀缺。这一层做出哪怕一个小例子，分量远超再多一篇 paper 复现。

十七、项目并行学习路线：每一层都要做出可展示成果

如果只按章节学习，最大的问题是：知识会停留在“我看过”。机器人岗位真正看重的是另一件事：

你能不能把一个系统跑起来、调稳定、记录问题、复盘失败，并把它讲清楚。

所以更好的路线不是“学完理论再做项目”，而是从第一层开始就并行做项目。理论负责解释为什么，开源项目负责暴露真实复杂度，履历产出负责证明你真的做过。

下面这张路线不是要求每个人全部做完，而是给每一层配一个“最小可展示项目”。如果时间有限，每一层只做一个也够；如果想冲击更强的机器人算法 / 工程岗位，可以把相邻两三层串成一个完整闭环。

17.1 数学与空间表示：从公式到可视化工具

这一阶段不要只刷线性代数和三维几何题。更好的做法是写一个小工具，把向量、矩阵、坐标变换和姿态表示直接画出来。

推荐项目：

  • NumPy + Matplotlib：自己写旋转矩阵、齐次变换、坐标轴可视化。
  • SciPy Rotation：练习欧拉角、旋转矩阵、四元数互转。
  • Sophus：学习 SO(3)、SE(3) 这类李群表示。
  • Open3D：把点云、坐标轴、相机外参画出来。

最小项目可以这样做：

  1. 给定一个相机坐标系、机械臂底座坐标系和世界坐标系。
  2. 随机生成一个 3D 点，分别显示它在三个坐标系下的坐标。
  3. 用 Open3D 或 Matplotlib 画出坐标轴和变换前后的点。
  4. 故意交换矩阵乘法顺序，记录错误结果长什么样。

履历表达可以写成：

  • 实现机器人坐标变换可视化工具，支持旋转矩阵、四元数、齐次变换与点云坐标转换。
  • 用可视化方式复现外参错误、坐标系左右手混用、变换顺序错误等典型问题。

这一层的价值在于：后面做 SLAM、机械臂、状态估计、人形控制时，坐标链不会一碰就乱。

17.2 运动学与机械臂：从二连杆到 MoveIt 2

运动学最适合做成一个“小而完整”的机械臂项目。不要一开始就追求人形全身控制，可以先从二维二连杆、三自由度机械臂、六轴机械臂逐步加复杂度。

推荐项目：

  • MoveIt 2：ROS 2 生态里的机械臂运动规划主力。
  • Pinocchio：机器人运动学、动力学计算非常常用。
  • Drake：适合做运动规划、轨迹优化和接触建模。
  • OMPL：采样式运动规划库，MoveIt 背后也常用它。
  • mujoco_menagerie：高质量机器人模型库，可以直接拿现成模型练控制。

最小项目可以这样做：

  1. 手写二连杆正运动学和逆运动学。
  2. 给一个目标点，实时显示末端轨迹和关节角变化。
  3. 再切到 MoveIt 2，加载一个机械臂 URDF。
  4. 用 RViz2 规划一条避障轨迹。
  5. 对比“手写 IK”和“MoveIt 规划”的差别。

履历表达可以写成：

  • 基于 MoveIt 2 搭建六轴机械臂运动规划 demo，完成 URDF 建模、逆运动学求解、轨迹规划与 RViz2 可视化。
  • 手写二连杆 IK，并与 MoveIt 2 / Pinocchio 的运动学结果交叉验证。

这一层最好留下三类材料：代码仓库、运行截图、短视频。机器人履历里，视频的说服力非常高。

17.3 概率滤波与状态估计：从传感器日志到可复现实验

状态估计不能只看卡尔曼滤波公式。更重要的是知道传感器数据长什么样，噪声怎么来，漂移怎么积累，滤波器失效时日志里会出现什么。

推荐项目：

  • robot_localization：ROS 生态常用 EKF/UKF 状态估计包。
  • VINS-Fusion：经典视觉惯性融合系统。
  • FAST-LIO：激光惯性里程计代表项目。
  • Kalibr：相机、IMU 标定工具。
  • evo：轨迹评估工具，适合算 ATE/RPE。

最小项目可以这样做：

  1. 下载一个公开 rosbag 或自己录一段 IMU + 里程计数据。
  2. 用 robot_localization 跑 EKF。
  3. 改变 IMU 噪声参数，观察轨迹如何发散。
  4. 用 evo 评估轨迹误差。
  5. 写一篇复盘：哪些参数最敏感，哪些现象像控制器问题但其实是估计问题。

履历表达可以写成：

  • 基于 robot_localization 构建 IMU / encoder 融合状态估计链路，完成 rosbag 回放、参数调优与轨迹误差评估。
  • 使用 evo 对不同滤波参数下的轨迹进行 ATE/RPE 对比，并定位漂移来源。

这类项目看起来没有“机器人跑起来”那么炫，但非常接近真实工程调试。

17.4 感知与 SLAM：从地图到可抓取目标

感知层最容易变成“跑了一个模型”。为了让履历更有分量，最好把它做成完整链路：传感器输入、标定、定位、目标识别、坐标转换、给规划器输出结果。

推荐项目：

  • ORB-SLAM3：视觉 SLAM 经典项目。
  • Open3D：点云处理、配准、重建。
  • COLMAP：SfM / MVS 经典工具。
  • nerfstudio：NeRF 工具链。
  • SAM 2、Grounding DINO：开放词汇分割和检测。

最小项目可以这样做：

  1. 用 RGB-D 相机或公开数据集生成点云。
  2. 用 Open3D 做点云滤波、平面分割、聚类。
  3. 用 SAM 2 或 Grounding DINO 找到目标物体。
  4. 把目标中心从相机坐标系变换到机械臂底座坐标系。
  5. 输出一个可供机械臂抓取的候选位姿。

履历表达可以写成：

  • 搭建 RGB-D 感知到抓取候选位姿的最小闭环，使用 Open3D 完成点云处理，并接入开放词汇分割模型输出目标区域。
  • 完成相机外参与机械臂底座坐标转换，将视觉检测结果转换为机器人任务空间目标。

这比“会用 YOLO / SAM”更强，因为你证明的是机器人感知闭环，而不是单张图片推理。

17.5 经典控制与动力学：从稳定站立到可解释失效

控制方向要避免只说“会 PID”。一个更好的项目路线是：先做机械臂轨迹跟踪，再做接触控制，最后进入腿式稳定或人形全身控制。

推荐项目：

  • Pinocchio：快速计算运动学、动力学、雅可比。
  • Crocoddyl：轨迹优化和最优控制。
  • OCS2：腿式机器人 MPC/最优控制代表。
  • ros2_control：ROS 2 控制框架。
  • Drake：接触、优化、规划综合框架。

最小项目可以这样做：

  1. 在 MuJoCo 或 Drake 里加载一个倒立摆、机械臂或简单腿式模型。
  2. 实现 PID / PD + feedforward 控制。
  3. 加入轨迹规划，记录跟踪误差。
  4. 加入扰动，观察恢复能力。
  5. 写失效分析：超调、振荡、饱和、延迟分别是什么表现。

履历表达可以写成：

  • 在仿真环境中实现机械臂轨迹跟踪控制，完成 PID / 前馈控制对比、扰动恢复实验与误差可视化。
  • 基于 Pinocchio 计算雅可比和动力学项，用于末端任务控制与力矩前馈。

真正有价值的不是“控制器能跑”，而是你能解释它为什么稳、为什么不稳。

17.6 仿真与强化学习：从单环境到 GPU 并行训练

仿真层是机器人学习和真实机器人之间的桥。现在前沿项目变化很快，建议长期跟踪 Isaac Lab、MuJoCo、Genesis 这三条线。

推荐项目：

  • Isaac Lab：NVIDIA 当前主推的机器人学习仿真与训练框架。
  • MuJoCo：DeepMind 维护的物理仿真器。
  • MuJoCo Playground：面向机器人学习的 MuJoCo 训练环境集合。
  • Genesis：面向高速并行仿真的新框架。
  • legged_gym、rsl_rl：腿式 RL 训练经典组合。
  • ManiSkill：操作类仿真与学习基准。

最小项目可以这样做：

  1. 先用 MuJoCo 跑一个机械臂 reach 或 cartpole 任务。
  2. 再用 Isaac Lab 跑一个现成 locomotion 任务。
  3. 改奖励函数，看训练曲线如何变化。
  4. 做一次 domain randomization，对比策略鲁棒性。
  5. 保存训练曲线、评估视频和配置文件。

履历表达可以写成：

  • 基于 Isaac Lab 复现腿式机器人 PPO 训练流程，完成并行环境配置、奖励函数调试、训练曲线分析与策略视频评估。
  • 基于 MuJoCo Playground 搭建最小机器人 RL 任务，对比不同随机化设置下的策略稳定性。

这一层尤其适合做视频展示。哪怕是真机之前的仿真 demo，也比只写“熟悉强化学习”更可信。

17.7 ROS 2 与系统工程：把模块接成一台机器人

很多机器人项目失败不是算法不行，而是系统组织混乱。ROS 2 这一层最适合做“工程化证明”。

推荐项目：

  • ROS 2：当前机器人中间件主线。
  • Nav2：移动机器人导航主力。
  • MoveIt 2：机械臂规划主力。
  • ros2_control：控制器管理和硬件抽象。
  • micro-ROS：MCU 接入 ROS 2。
  • Foxglove 与 rerun：可视化、日志和调试工具。

最小项目可以这样做：

  1. 写一个 ROS 2 节点发布模拟 IMU / joint state。
  2. 写另一个节点订阅状态并发布控制命令。
  3. 用 TF2 管理坐标链。
  4. 用 rosbag2 录制一次失败过程。
  5. 用 Foxglove 或 rerun 回放并标注问题。

履历表达可以写成：

  • 基于 ROS 2 搭建机器人最小系统，包含 TF2 坐标链、ros2_control 控制器、rosbag2 数据回放与 Foxglove 可视化调试。
  • 通过 rosbag2 复现实验故障，定位传感器时序、坐标外参和控制参数问题。

这类项目对工程岗非常加分，因为它说明你不是只会单点算法。

17.8 机器人学习与 VLA：从模仿学习到开放模型

机器人学习是目前变化最快的部分。这里不要盲目追新模型，而要选择一条能落地的小任务，比如夹爪抓取、双臂遥操、桌面整理或移动操作。

推荐项目：

  • LeRobot：Hugging Face 的机器人学习工具链，适合低成本入门。
  • Diffusion Policy：扩散策略做机器人操作的经典基线。
  • ACT / ALOHA：双臂遥操作与 action chunking。
  • OpenVLA：开源 VLA 模型路线代表。
  • openpi：Physical Intelligence 开源的机器人模型与策略代码方向，适合跟踪 pi 系列相关生态。
  • robomimic：模仿学习基准。

最小项目可以这样做：

  1. 用 LeRobot 跑通一个低成本机械臂或公开数据集任务。
  2. 复现 Diffusion Policy 的一个桌面操作任务。
  3. 记录数据格式、训练脚本、推理频率和失败样例。
  4. 如果硬件允许，再做 10-30 条自己的示教数据。
  5. 对比“训练集内动作”和“稍微改变物体位置”后的泛化能力。

履历表达可以写成：

  • 基于 LeRobot / Diffusion Policy 复现桌面操作模仿学习任务，完成数据采集、训练、推理部署和失败案例分析。
  • 跟踪 OpenVLA / openpi 等 VLA 项目，整理模型输入输出、动作表示和机器人本体适配方式。

这一层最容易“看起来很前沿但没有工程细节”。要把细节写出来：数据多少条、动作频率多少、失败率多少、为什么失败。

17.9 硬件与部署：把开源项目接到真实设备

硬件不一定要一步到位做人形。更现实的路线是先从电机、驱动器、编码器、机械臂或小车开始，把控制链路跑通。

推荐项目：

  • SimpleFOC：低门槛 BLDC FOC 控制。
  • ODrive：开源电机驱动生态。
  • moteus：机器人常用电机控制器。
  • SOEM：EtherCAT 主站实现。
  • ONNX Runtime、TensorRT、OpenVINO：部署和推理加速。

最小项目可以这样做：

  1. 用 SimpleFOC 或 ODrive 跑通一只无刷电机。
  2. 记录电流环、速度环、位置环的调参过程。
  3. 把上位机控制命令通过串口、CAN 或 ROS 2 发到驱动器。
  4. 如果做学习策略，把 PyTorch 模型导出 ONNX。
  5. 测一次端到端延迟：传感器输入到动作输出需要多久。

履历表达可以写成：

  • 基于 SimpleFOC / ODrive 完成 BLDC 电机速度与位置控制，记录电流、速度、位置三环调试流程。
  • 将 PyTorch 机器人策略导出 ONNX，并在边缘设备上完成推理频率、延迟和稳定性测试。

这一层能显著区分“算法简历”和“机器人系统简历”。

17.10 项目选择原则：不要贪多，要形成闭环

开源项目很多，不需要都做。更推荐按下面原则选：

  1. 能跑起来：优先选择文档清楚、社区活跃、示例完整的项目。
  2. 能改参数：只跑 demo 不够，至少要改一个核心参数并解释影响。
  3. 能记录失败：机器人项目的失败案例比成功截图更有价值。
  4. 能接上下游：感知结果能不能给规划器，仿真策略能不能导出，控制器能不能接 ros2_control。
  5. 能展示：每个项目都应该留下 README、配置、截图、视频、日志和复盘。

一份比较扎实的机器人项目履历，最好不是十个零散 demo，而是三条完整线：

  • 感知线：RGB-D / SLAM -> 坐标变换 -> 目标位姿 -> 机械臂抓取候选。
  • 控制线：URDF / 动力学 -> 轨迹规划 -> 控制器 -> 扰动恢复与误差分析。
  • 学习线：仿真环境 -> 数据 / 奖励 -> 训练 -> 评估视频 -> 部署或迁移分析。

每条线最后都应该能回答四个问题：

  1. 输入是什么？
  2. 输出是什么？
  3. 中间用了哪些开源项目？
  4. 系统在哪些条件下会失败？

能把这四个问题讲清楚，履历就会从“学过机器人”变成“做过机器人系统”。

十八、三条典型成长支路

如果不打算“全栈通吃”，可以选下面一条作为主线，其余作为支持知识。

A. 感知 / SLAM 方向

  • 主依赖层：数学基础 -> 空间表示 -> 概率与滤波 -> 感知与三维理解 -> 中间件
  • 重点项目：ORB-SLAM3、VINS-Fusion、FAST-LIO2、Open3D、Kalibr、SAM 2
  • 适配岗位：SLAM 工程师、感知工程师、AR / VR 与无人机感知岗

B. 控制 / 动力学 / 运动规划方向

  • 主依赖层：数学基础 -> 空间表示 -> 运动学 -> 概率与滤波 -> 机械臂 / 四足 / 人形控制 -> 仿真
  • 重点项目：Pinocchio、Drake、Crocoddyl、OCS2、ros2_control、legged_gym
  • 适配岗位：四足 / 人形控制工程师、机器人算法工程师、机械臂运动规划岗

C. 机器人学习 / RL / VLA 方向

  • 主依赖层：数学基础 -> 运动学 -> 仿真 -> 机器人学习 -> 部署
  • 重点项目：Isaac Lab、legged_gym、Diffusion Policy、LeRobot、OpenVLA、Octo
  • 适配岗位：机器人学习算法工程师、具身大模型方向、灵巧操作算法工程师

三条路并不排他——但单段时间内只押注一条，迭代速度会更快。

十九、推荐阅读顺序

如果从零开始，建议按下面顺序读：

  2. 具身智能中的坐标系、旋转矩阵与四元数

  6. 机械臂控制基础：轨迹规划、PID 与末端控制
  7. 具身智能中的接触与抓取：从机械臂到灵巧手
  8. 四足机器人控制基础：足端轨迹、质心与稳定性
  9. 人形机器人控制基础：质心、ZMP 与步态

  11. 人形机器人中的全身控制实现：从动力学方程到 QP 求解

如果目标是人形，建议不要跳过第 1 到第 5 篇，因为后面所有全身控制、状态估计和环境交互都依赖这些基础。

二十二、总结

机器人与具身智能全栈开发，最怕学习顺序断层。

如果只看上层模型，很容易忽略硬件、控制和状态估计。

如果只看底层驱动，又很难把机器人推向复杂任务。

这套路线的核心目标，是把这些层串起来：

每往下一层，问题就更具体、对工程能力的要求就更明确。本文不要求所有人都覆盖全部 14 层，但建议每条主线（感知 / 控制 / 学习）都至少做出一份能演示、能复盘的成果。

机器人不是把大模型接到电机上，而是把数学、感知、状态、控制、接触、学习与硬件约束逐层闭环，最终让智能拥有一个可计算、可控制、可恢复、可交付的身体。
