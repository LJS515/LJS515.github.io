MPC 在腿式机器人里的工程实现：从模型预测到实时控制

前面的四足与人形文章已经建立了几个关键概念：

  • 足端轨迹与落脚点
  • 质心与支撑关系
  • 接触力分配
  • 全身控制与 QP
  • 浮动基状态估计

当机器人只需要慢速站立或执行固定步态时，规则、轨迹生成和局部反馈已经能做出可用原型。

但如果目标变成：

  • 更快的小跑
  • 速度与转向指令跟踪
  • 复杂地形上的连续落脚
  • 推搡后的恢复
  • 接触力、摩擦和硬件限制同时满足

控制器就必须提前考虑未来几个时刻。

这正是 MPC 的进入点。

MPC 全称是 Model Predictive Control，也就是模型预测控制。它的核心不是”预测得越远越好”，而是：

用一个足够快的模型在线预测未来，在约束内选出当前最值得执行的第一步，然后拿到新状态继续重算。

这使 MPC 同时具备两种能力：

  1. 比纯反馈控制更早看到未来约束。
  2. 比离线轨迹更能适应扰动和模型误差。

二、腿式机器人为什么特别需要 MPC

腿式机器人比轮式机器人多了一层麻烦：

接触会切换。

每条腿都可能在支撑相和摆动相之间变化。支撑腿可以给地面施加力，摆动腿不应该凭空产生地面反作用力。

因此控制器面对的不是一个始终固定的系统，而是一个随时间切换的系统：

例如四足小跑步态里，对角腿会成对切换。控制器必须提前知道：

  • 下一时刻哪些腿还在支撑
  • 哪些腿即将离地
  • 哪些腿即将落地
  • 支撑力如何平滑转移
  • 未来落脚点是否还能支撑期望速度

MPC 的价值就是把这些未来接触关系纳入计算。

三、先用什么模型：质心动力学

实时 MPC 的第一项工程决策不是求解器，而是模型复杂度。

如果直接把整台四足或人形机器人的所有关节、刚体和接触都塞进在线优化，问题会很重。

工程上常见做法是先用简化模型做 MPC，再把结果交给下层控制器。

腿式机器人里非常常见的是质心动力学模型。

3.1 质心模型保留什么

质心模型重点保留：

  • 机身位置
  • 机身速度
  • 机身姿态
  • 机身角速度
  • 各支撑脚接触力
  • 接触位置

为了让整体机身按期望运动，各条支撑腿应该提供什么接触力。

3.2 简化模型的代价

模型越简单，求解越快，但误差越大。

常见误差包括：

  • 忽略腿部惯量
  • 忽略柔性和间隙
  • 地面摩擦估计不准
  • 接触位置有偏差
  • 状态估计有延迟

时域太短时，控制器可能看不到下一次接触切换，动作会变得短视。

时域太长时：

  • 决策变量更多
  • 求解时间更长
  • 远端预测更不可靠
  • 实时性更难保证

工程上要围绕步态周期和算力做选择。

一个实用检查方法是：

  1. 时域能否覆盖至少一次关键接触切换。
  2. 求解器的 p95_solve_time_ms 是否稳定低于 MPC 周期。
  3. 扰动后是否能在数个周期内恢复。
  4. CPU 抢占和日志写入后是否仍有余量。

五、接触约束是 MPC 的硬骨头

没有接触约束，腿式 MPC 很容易给出数学上漂亮、物理上不可能的结果。

5.3 摩擦约束不能超限

约束不是为了让公式更完整，而是为了让结果能交给真机。

六、落脚点规划和 MPC 怎么配合

接触力回答的是：

已经踩住的脚应该怎么发力。

落脚点规划回答的是：

下一步应该踩在哪里。

在平地慢速小跑里，可以先用简单规则：

进入台阶、石块或坡地后，落脚点还要考虑：

  • 地面高度
  • 坡度
  • 可踩区域
  • 足端碰撞
  • 腿部工作空间
  • 下一阶段支撑裕度

常见分工有两类：

  1. 上层先给可行落脚区域，MPC 在其上优化机身与接触力。
  2. MPC 同时优化部分落脚点变量，但要控制问题规模。

不要一开始就把地形感知、落脚点搜索、质心轨迹和全身动力学全部塞进一个优化器。先跑通平地闭环，再逐层加复杂度。

七、MPC 和 WBC 的关系

MPC 和 WBC 经常同时出现，但它们不是同一个东西。

7.1 MPC 负责看未来

MPC 更关注：

  • 未来质心轨迹
  • 机身姿态
  • 接触模式
  • 地面反作用力
  • 约束下的可行性

它输出的通常是：

7.2 WBC 负责把目标变成全身动作

WBC 全称是 Whole-Body Control，也就是全身控制。

它更关注：

  • 浮动基动力学
  • 关节加速度
  • 关节力矩
  • 足端任务
  • 接触雅可比
  • 关节与力矩限制

它把 MPC 目标转成机器人当前时刻可以执行的命令：

7.3 为什么要分层

因为两层面对的时间尺度不同。

MPC 不需要独自承担所有关节级细节。WBC 也不应该只顾当前瞬间，完全看不到未来接触切换。

八、OCS2 为什么值得重点看

OCS2 是 ETH Zurich Robotic Systems Lab 开源的最优控制软件库。官方文档把它描述为面向机器人系统的最优控制工具箱，覆盖从系统建模、约束和代价定义，到 MPC 接口与机器人部署所需的 MRT 接口。

官方资料：

  • OCS2 GitHub 仓库
  • OCS2 官方文档
  • OCS2 Legged Robot 示例

8.1 OCS2 里值得关注什么

对腿式机器人，建议优先理解：

  • 状态和输入如何定义
  • 质心动力学模型如何接入
  • 接触模式如何切换
  • 代价函数如何拆分
  • 约束如何表达
  • MPC 和 MRT 如何通信
  • 求解时间如何记录

OCS2 官方文档列出了多类最优控制算法，包括 SLQ、iLQR、SQP 和 IPM 路线。不要一上来纠结哪一种算法最强，先用示例理解数据流。

8.2 legged_control 可以作为工程参考

legged_control 是一个基于 OCS2、Pinocchio 与 ROS control 的腿式机器人控制开源项目。它把 MPC、WBC 和仿真链路放在一个可运行工程里，适合观察模块边界。

阅读顺序建议：

  1. 先看配置文件里的状态权重、输入权重和接触参数。
  2. 再看 MPC 输出如何进入 WBC。
  3. 再看仿真启动方式和日志。
  4. 最后才改模型和求解器。

九、一个最小仿真实践怎么做

个人作品集不需要一开始就追求复杂地形。

更稳妥的四阶段路线是：

9.1 阶段一：固定接触站立

目标：

验证：

  • 接触力总和是否接近机器人重量
  • 四条腿法向力是否为正
  • 姿态扰动后是否恢复

9.2 阶段二：平地速度跟踪

目标：

验证：

  • 速度跟踪误差
  • 接触切换处的力跳变
  • 求解器耗时
  • 是否出现 deadline miss

9.3 阶段三：外力扰动恢复

给机身施加侧向或前后扰动。

验证：

  • 姿态恢复时间
  • 最大质心偏差
  • 是否打滑
  • 是否需要调整落脚点

9.4 阶段四：简单地形

加入低台阶、缓坡或高度扰动。

验证：

  • 足端是否踩入可行区域
  • 接触估计是否滞后
  • 摩擦系数变化是否导致失败
  • 模型简化是否仍然可接受

仿真器可以从 MuJoCo 开始，也可以使用 OCS2 示例、Gazebo 或项目已有的仿真环境。

十、调试时不要只看机器人摔没摔

MPC 调试最怕只看最终视频。

一次失败至少要记录下面几组数据。

10.1 状态估计

10.2 优化器

10.3 接触

10.4 跟踪误差

看到失败后，按顺序排查：

  1. 状态估计是否先漂了。
  2. 接触模式是否错位。
  3. 预测时域是否覆盖关键切换。
  4. 摩擦和力约束是否过松或过紧。
  5. WBC 是否能跟上 MPC 输出。
  6. 求解器是否在控制周期内完成。

十一、常见失败模式

11.1 求解器偶发超时

平均耗时看起来没问题，但 max_solve_time_ms 偶尔超过周期。

处理：

  • 减少预测步数
  • 降低模型复杂度
  • 减少不必要约束
  • 预分配内存
  • 隔离实时线程
  • 记录超时后的降级策略

11.2 机器人频繁打滑

处理：

  • 检查摩擦系数
  • 检查足底材料和仿真参数
  • 检查切向力是否接近边界
  • 降低期望加速度
  • 增加落脚点补偿

11.3 接触切换时机身抖动

处理：

  • 检查接触模式和实际触地是否一致
  • 给接触力变化加平滑项
  • 检查摆动腿落地速度
  • 检查 WBC 权重

11.4 MPC 输出合理，但关节执行很差

这通常不是 MPC 单层问题。

继续检查：

  • WBC 任务优先级
  • 关节力矩限制
  • 电机带宽
  • 通信延迟
  • 状态时间戳

十二、开源项目清单

建议按用途选择，不要全部堆进一个项目。

12.1 MPC 与最优控制

  • OCS2：腿式机器人实时 MPC 的重点学习项目。
  • Crocoddyl：机器人轨迹优化与最优控制库。
  • Drake：包含建模、规划、控制和仿真工具。

12.2 动力学

  • Pinocchio：快速刚体动力学与雅可比计算。

12.3 工程参考

  • legged_control：OCS2、Pinocchio、ROS control、MPC 与 WBC 集成参考。
  • MuJoCo：适合构建可复现实验和扰动测试。

12.4 论文入口

  • Dynamic Locomotion in the MIT Cheetah 3 Through Convex Model-Predictive Control：理解四足凸 MPC 的经典入口。
  • Perceptive Locomotion through Nonlinear Model Predictive Control：理解地形感知、落脚点与 NMPC 协同的重要参考。

前沿项目更新很快。实现前应再次查看官方仓库 README、分支与依赖说明。

  6. 一次失败案例复盘。
  7. README 中写清楚 MPC 与 WBC 的分工。

十四、简历表达怎么写

不要只写：

更好的表达是：

  • 基于 OCS2 搭建四足机器人质心动力学 MPC，完成接触模式切换、摩擦约束、接触力优化与平地速度跟踪仿真。
  • 将 MPC 输出接入 WBC / QP 控制层，记录 mean / p95 / max 求解延迟并分析接触切换阶段的姿态误差与力跳变。
  • 在 MuJoCo 或 Gazebo 中完成外力扰动、摩擦变化和简单地形回归测试，整理失败日志与参数敏感性报告。

面试时要能回答：

  1. 为什么 MPC 不直接优化所有关节。
  2. 预测时域为什么不能无限加长。
  3. 摩擦约束如何影响打滑。
  4. MPC 与 WBC 各自跑多快。
  5. 求解器超时时系统如何降级。

十五、核心结论

  1. MPC 的本质是滚动时域在线优化，不是一次性轨迹生成。
  2. 腿式机器人需要 MPC，是因为未来接触切换会直接影响当前动作。
  3. 质心动力学在模型精度和实时性之间提供了实用平衡。
  4. 接触力、摩擦和法向力约束决定优化结果能不能交给真机。
  5. 落脚点规划回答”下一步踩哪里”，MPC 回答”未来怎么稳住并跟踪目标”。
  6. MPC 负责看未来，WBC 负责把目标落到全身关节与力矩。
  7. 一个可信作品集必须同时展示闭环效果、求解耗时、约束状态和失败复盘。

做到这里，你就不只是”看过 MPC”，而是开始具备把优化控制塞进实时机器人系统的工程能力。
