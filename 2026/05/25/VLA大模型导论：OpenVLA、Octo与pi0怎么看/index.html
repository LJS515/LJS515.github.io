VLA 大模型导论：OpenVLA、Octo 与 pi0 怎么看

前面两篇，我们已经讲了机器人学习里的两条主线：

  • 强化学习：在仿真或环境交互中，通过 reward 学策略。
  • 模仿学习：从人类示教数据中学习动作，重点做数据闭环。

这篇继续往上走，讲当前机器人学习最容易被讨论、也最容易被误解的一类模型：

VLA，Vision-Language-Action，视觉-语言-动作模型。

如果把传统机器人系统写成一条链：

VLA 想做的事情是把其中一部分高层决策和动作生成合并成一个数据驱动策略：

听起来很像“把大模型接到机械臂上”。但这句话太粗糙，也很危险。

更准确地说：

VLA 是把视觉理解、语言指令和机器人动作预测放到同一个策略模型里，用大规模机器人数据和视觉语言预训练能力，提高跨任务、跨场景、跨本体的泛化能力。

这篇文章的目标不是追热点，而是把 VLA 放回机器人工程里：

  • VLA 到底比普通模仿学习多了什么
  • 图像、语言、动作如何进入同一个模型
  • OpenVLA、Octo、pi0 分别代表什么路线
  • Open X-Embodiment、DROID、LeRobot 为什么重要
  • 如何微调、评估和部署一个 VLA
  • 个人作品集应该怎么做，才不是“读过几篇 VLA 论文”

一、VLA 不是让语言模型直接控制电机

很多人第一次听 VLA，会自然想到：

这只说对了一小部分。

机器人不是文本游戏。机器人动作必须满足：

  • 实时性
  • 连续性
  • 安全边界
  • 物理约束
  • 相机和关节状态闭环
  • 低层控制器可执行

所以 VLA 通常不是输出一大段自然语言计划，而是输出机器人能执行的动作。

动作可以是：

  • 末端 delta pose
  • 关节目标
  • 夹爪命令
  • action token
  • action chunk
  • 低层 policy 的条件输入

语言带来三个价值。

第一，任务条件更灵活。

同一个场景，不同指令，对应不同动作。

第二，数据可以跨任务混合。

不同数据集里的任务如果都有语言标注，就更容易被放进同一个训练混合里。

第三，可以继承视觉语言模型的语义理解。

VLM 在互联网图文数据上学到过大量物体、场景、关系和常识。VLA 试图把这些能力迁移到机器人动作上。

但注意，这不等于 VLA 天然懂物理。

VLM 见过“杯子”“抽屉”“衣服”，不代表它知道夹爪接触杯子时会滑，也不代表它知道衣服会皱、纸箱会弹开、线缆会缠住。

所以 VLA 的难点是：

少任何一环，都只是看起来像机器人智能。

三、VLA 的输入输出怎么设计

一个 VLA 项目，首先要看四个接口。

3.1 图像输入

常见图像输入包括：

  • front camera
  • wrist camera
  • multiple external cameras
  • depth image
  • cropped object view

图像输入的核心问题不是“分辨率越高越好”，而是：

  • 能不能看到关键接触区域
  • 训练和部署裁剪是否一致
  • 多相机是否时间同步
  • 光照和背景变化是否覆盖
  • wrist camera 是否会运动模糊

如果 VLA 在训练时看到的是干净实验台，部署时面对反光桌面和杂物，它的语言能力救不了视觉分布偏移。

3.2 语言输入

语言标注最好和任务成功条件一致。

如果数据里写的是“整理桌子”，但成功条件其实是“把杯子放进托盘”，模型会学得很混乱。

3.3 机器人状态

VLA 不一定只看图像。

机器人状态通常很有用：

  • joint positions
  • joint velocities
  • end effector pose
  • gripper width
  • previous action

状态输入能帮助模型判断“自己现在在哪里”。尤其是手眼相机被遮挡、物体被夹爪挡住时，关节状态和历史动作很关键。

3.4 动作输出

动作输出是 VLA 项目的核心。

常见选择：

动作表示没有绝对最好，只有是否匹配硬件和控制器。

如果你的底层控制器是末端伺服，输出末端 delta pose 会更自然。

如果你的系统有稳定的关节控制接口，输出 joint target 可能更直接。

如果模型采用离散 token，就要关注 tokenization 是否损失精度。

如果模型输出连续 chunk，就要关注推理频率、动作平滑和安全限幅。

四、OpenVLA：开源 7B VLA 基线

OpenVLA 是学习 VLA 很重要的入口。

截至 2026 年 5 月，OpenVLA 官方 README 仍把它定位为开源 VLA 训练和微调代码库，提供：

  • openvla-7b 预训练模型
  • Hugging Face transformers 推理接口
  • LoRA fine-tuning 示例
  • full fine-tuning 示例
  • Open X-Embodiment / RLDS 数据混合支持
  • REST API serving 脚本
  • BridgeData / LIBERO 等评估入口

OpenVLA 的核心价值不是“7B 很大”，而是它把 VLA 变成了可复现工程对象。

你可以读它来理解：

  • VLM backbone 如何接动作输出
  • robot dataset 如何转成训练样本
  • action normalization 怎么做
  • fine-tuning 需要多少显存
  • 推理服务如何接进机器人控制栈
  • 为什么 action tokenization 会影响速度和精度

OpenVLA 官方更新中提到的 FAST action tokenizer 和 OFT fine-tuning recipe 也很值得关注。

它们背后都是同一个工程问题：

机器人和聊天机器人不同。聊天慢一秒只是体验差，机器人慢一秒可能已经错过接触窗口。

五、Octo：通用机器人策略 transformer

Octo 是另一个很适合学习的开源通用机器人策略。

官方仓库把 Octo 描述为 trained on a diverse mix of 800k robot trajectories 的 transformer-based robot policy。

它和 OpenVLA 的气质不太一样。

OpenVLA 更像 VLM 到 action 的路线，强调开源 VLA、语言条件和大模型微调。

Octo 更像机器人策略本身的通用化路线，强调：

  • 多任务
  • 多数据集
  • 机器人 trajectory
  • action head
  • fine-tuning 到新任务

学习 Octo 时，不要只看模型结构。更重要的是看它如何组织机器人数据：

Octo 对个人作品集的价值在于：它可以帮助你理解“通用机器人策略”不是一句口号，而是大量数据格式和动作接口对齐之后的结果。

六、pi0 与 openpi：从展示到可试验代码

Physical Intelligence 在 2024 年 10 月发布 pi0，把它称为 first generalist policy。官方博客强调 pi0 结合图像、文本和动作，使用多机器人、多任务数据，并可以通过提示或微调执行任务。

到 2026 年 5 月，更适合工程学习者看的入口是 openpi。

截至 2026 年 5 月，openpi README 里已经包含三类模型：

  • pi0：flow-based VLA
  • pi0-FAST：基于 FAST action tokenizer 的 autoregressive VLA
  • pi0.5：强调更好 open-world generalization 的升级版本

README 还说明了几个非常工程化的信息：

  • base checkpoints 预训练在 10k+ hours robot data 上
  • 提供 DROID、ALOHA、LIBERO 等相关 checkpoint 或示例
  • 支持用 LeRobot dataset 做微调数据转换
  • 推理最低建议 NVIDIA GPU 8GB 以上
  • LoRA fine-tuning 需要更高显存
  • full fine-tuning 通常需要 A100 / H100 级别
  • 提供 remote inference，把模型放在服务器上，通过网络把动作发给机器人

这说明 VLA 正在从“论文和视频”变成“普通研究者可以试验的工程栈”。

但 openpi README 也提醒得很清楚：pi0 是实验性项目，原始模型是在他们自己的机器人上开发的，迁移到 ALOHA、DROID 等常见平台不保证每次成功。

这句话非常重要。

VLA 不是魔法。你拿到 checkpoint 后，仍然要解决：

  • camera layout 差异
  • action space 差异
  • robot embodiment 差异
  • calibration 差异
  • latency 差异
  • task distribution 差异

七、RT-X 与 Open X-Embodiment：数据规模化的起点

VLA 的真正壁垒不是模型名字，而是机器人数据。

语言模型能吃互联网文本，视觉模型能吃互联网图像，但机器人数据昂贵得多。

一条机器人轨迹需要：

  • 真实机器人
  • 相机和传感器
  • 可执行任务
  • 遥操作或自动策略
  • 时间同步
  • 动作记录
  • 成功标注
  • 安全场地

Open X-Embodiment 的意义就在这里。它把多个机构、多个机器人、多个任务的数据混到一起，推动 RT-X 这类跨本体策略。

上一篇模仿学习里提到过，Open X-Embodiment 项目页显示它汇集 22 种机器人本体、60 个数据集、1M+ 真实机器人轨迹。

这些数字的意义不是“越大越好”，而是：

当然，跨本体数据也会带来麻烦。

不同机器人可能有：

  • 不同自由度
  • 不同夹爪
  • 不同相机位置
  • 不同动作频率
  • 不同 action space
  • 不同任务标注

所以 VLA 工程里，数据转换和动作适配是核心能力。

VLA 模型大，部署时延迟非常关键。

所以 VLA 部署常见有三种方式。

第二，远程推理服务器。

优点是算力强，缺点是网络延迟和稳定性。

第三，VLA 做高层，低层策略做执行。

这通常更安全，也更符合机器人系统分层。

十、安全：大模型策略必须被关在安全边界里

VLA 输出动作，不代表它应该直接控制机器人。

至少要有四层保护。

第一，动作限幅。

第二，workspace 限制。

第三，速度和加速度限制。

第四，急停和人工接管。

更进一步，可以加入影子模式。

影子模式很适合 VLA 项目，因为它能在不冒险的情况下收集策略表现。

十四、截至 2026 年 5 月的前沿观察

第一，VLA 已经从封闭展示走向开源可试验。

OpenVLA、Octo、openpi 都让学习者能看到真实代码、数据格式、checkpoint 和评估脚本。虽然复现成本仍然不低，但已经不是只能看视频。

第二，动作表示正在成为关键竞争点。

离散 action token、连续 action chunk、flow matching、FAST tokenizer、OFT fine-tuning，背后都在解决同一个问题：

第三，数据集和本体适配比模型名字更重要。

VLA 的泛化来自数据多样性，但部署失败也常常来自本体差异：

  • 你的相机不一样
  • 你的夹爪不一样
  • 你的 action space 不一样
  • 你的控制频率不一样
  • 你的任务分布不一样

第四，VLA 不会取消控制和安全工程。

越大的策略，越需要更清楚的边界。安全限幅、急停、日志、回放、影子模式会越来越重要。

第五，个人学习者最值得押注的是“会适配”。

不是每个人都能预训练大模型，但你可以掌握：

  • 数据格式转换
  • LoRA / adapter 微调
  • action normalization
  • rollout evaluation
  • latency profiling
  • safety wrapper

这些能力很实际，也更容易在面试里讲清楚。

十六、这篇的核心结论

VLA 不是“语言模型控制机器人”。

它是一条把视觉、语言、动作和机器人数据放到一起的策略学习路线：

这篇最重要的结论有六个：

  1. VLA 的价值在于语言条件、多任务数据和跨场景泛化，而不是模型参数量本身。
  2. OpenVLA 是开源 7B VLA 基线，适合学习 VLA 微调、推理和机器人控制栈接入。
  3. Octo 是通用机器人策略 transformer，适合理解多数据集机器人 policy 如何组织。
  4. openpi 把 pi0、pi0-FAST、pi0.5 变成可试验工程栈，但迁移到你的机器人仍然需要适配。
  5. VLA 项目最容易出问题的是动作表示、延迟、本体差异和安全边界。
  6. 能写进履历的 VLA 项目，必须包含数据 schema、微调、推理部署、延迟评估、失败复盘和安全 wrapper。

如果要用一句话总结：

这也是这条机器人全栈路线一直在强调的东西：模型越强，工程闭环越不能弱。
