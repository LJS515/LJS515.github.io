机器人部署与上线：ONNX、TensorRT、安全包络与影子模式

前面我们已经把机器人系统的几条关键线索铺开了：

  • 数学、运动学、状态估计
  • 感知、机械臂、腿式和人形控制
  • 仿真、ROS 2、强化学习、模仿学习、VLA
  • 电机、驱动器、总线和 ros2_control

到这里，一个机器人项目经常会进入最容易被低估的一段：

部署与上线。

很多项目在论文、视频和实验室 demo 里看起来已经完成了，但一旦要放到真实机器人上稳定运行，就会暴露出另一类问题：

  • 模型推理太慢
  • PyTorch 环境太重
  • 算子导出失败
  • 边缘设备显存不够
  • 控制周期被推理阻塞
  • 策略偶发输出危险动作
  • 真机失败没有日志
  • 新模型上线后没有回退路径

所以这篇文章的目标不是讲“怎么点一下 export”，而是讲一条完整工程链路：

这也是机器人项目从“能跑”到“能交付”的分界线。

二、为什么要从 PyTorch 导出

训练时用 PyTorch 很舒服。

但真机部署时，直接跑 PyTorch 可能遇到问题：

  • 环境依赖重
  • 启动慢
  • 显存占用高
  • 推理延迟不稳定
  • 边缘设备支持有限
  • 和 C++ 控制栈集成麻烦

ONNX 的价值是中间表示。

它让模型从训练框架里解耦出来，方便交给不同推理后端：

  • ONNX Runtime
  • TensorRT
  • OpenVINO
  • TVM
  • 其他厂商运行时

但 ONNX 不是万能转换器。

你必须检查：

  • 算子是否支持
  • 动态 shape 是否正确
  • 输入输出名字是否稳定
  • 数值误差是否可接受
  • batch 维度是否符合部署
  • 图像预处理是否在模型外还是模型内

十一、边缘设备选型不要只看 TOPS

边缘设备选型常见误区是只看算力。

但机器人上还要看：

  • 功耗
  • 散热
  • 启动时间
  • 接口数量
  • 相机带宽
  • 网络延迟
  • 实时线程隔离
  • 驱动支持
  • TensorRT / CUDA / OpenVINO 支持
  • 供电稳定性

Jetson、x86 + NVIDIA GPU、Intel 平台、国产边缘板卡都可能出现在项目里。

选型时应该从任务反推：

如果任务只是 10 Hz 视觉抓取，不一定需要最高端设备。

如果是高频多相机 VLA 或人形全身感知，边缘算力和散热就会成为主线问题。

十五、截至 2026 年 5 月的前沿观察

第一，部署栈正在更重视端侧大模型。

Jetson Thor、TensorRT 10.x、TensorRT-LLM、ONNX Runtime 和 OpenVINO 的持续更新，说明机器人端侧推理正在从小模型走向多模态和 VLA。

第二，ONNX 仍然是个人项目最实用的中间层。

即使最终用 TensorRT 或 OpenVINO，加一个 ONNX 导出和数值对齐步骤，能显著降低部署调试难度。

第三，机器人部署会越来越强调安全和可观测性。

只看成功视频不够。未来更重要的是：

  • latency profile
  • safety violation
  • replay log
  • rollback
  • shadow mode evaluation

第四，模型越强，安全包络越重要。

VLA、Diffusion Policy、强化学习策略都可能在分布外状态下输出危险动作。把策略关在安全边界里，是机器人部署的基本功。

十六、这篇的核心结论

机器人部署不是导出一个模型文件。

它是一条工程闭环：

这篇最重要的结论有六个：

  1. PyTorch checkpoint 只是训练产物，不等于部署产物。
  2. ONNX 的价值是中间表示，但必须做算子检查和数值对齐。
  3. TensorRT、ONNX Runtime、OpenVINO 的选择要围绕设备、延迟和维护成本。
  4. 机器人推理要纳入控制频率和延迟预算，不能挤爆实时控制环。
  5. 安全包络和影子模式是学习策略上线前的必要缓冲层。
  6. 能写进履历的部署项目必须有导出、加速、延迟、ROS 2 接入、安全、日志和回退。
