机器人强化学习入门：PPO、legged_gym 与 Sim2Real

前面我们已经把机器人系统的几条主线铺开了：

  • 数学基础
  • 坐标系和运动学
  • 概率滤波和状态估计
  • 感知与三维理解
  • 机械臂、四足、人形控制
  • 仿真平台
  • ROS 2 系统工程

这些内容解决的是一个问题：

如何把机器人建模清楚、控制稳定、系统接起来。

但机器人走到更复杂的任务时，会遇到另一类问题。

例如：

  • 四足机器人在复杂地形上如何自己学会步态调整
  • 人形机器人如何在高维接触下保持稳定
  • 机械臂如何在大量物体和姿态变化中学习抓取策略
  • 策略如何在仿真中大量试错，而不是每次都拿真机撞风险
  • 已经训练好的策略如何部署到 ROS 2 或真机控制栈中

这就是机器人强化学习的位置。

它不是经典控制的替代品，也不是把 PPO 一跑就能变成机器人专家。

更准确地说：

机器人强化学习是一套用仿真大规模试错，把策略、奖励、环境随机化和部署评估串成闭环的方法。

这篇文章不追求把强化学习理论推到很深，而是把你真正做机器人项目时需要掌握的主线讲清楚：

  • 强化学习在机器人系统里到底学什么
  • PPO 为什么在机器人里这么常见
  • legged_gym、rsl_rl、Isaac Lab 这些项目各自解决什么
  • 奖励函数为什么比算法名字更重要
  • Sim2Real 到底要补哪些工程缺口
  • 一个能写进履历的机器人 RL 项目应该长什么样

一、先把强化学习放回机器人系统里

很多人第一次学强化学习，会从 Gym 里的 CartPole、Atari 或小游戏开始。

这没有问题，但机器人强化学习和普通 RL 教程有明显区别。

机器人里最重要的不是“能不能训练出高奖励”，而是：

训练出来的策略能不能稳定、可解释、可复现，并且最终能接近真实机器人。

一个典型机器人强化学习闭环大致是：

如果你只会跑一条训练命令，但不知道奖励怎么设计、观测怎么选、为什么 sim 里能跑真机却摔，那么项目含金量很有限。

真正有价值的是能讲清楚这条闭环。

1.1 强化学习里的五个核心对象

机器人 RL 里最常见的五个对象是：

  • state：环境真实状态，仿真器知道，但策略不一定全部能看到
  • observation：策略实际输入，来自传感器或仿真观测
  • action：策略输出，可能是关节目标、速度、力矩或残差控制量
  • reward：任务目标和约束的数值化表达
  • policy：从 observation 到 action 的映射

可以用一个简单 ASCII 关系表示：

仿真器可能知道机器人完整状态：

  • base pose
  • base velocity
  • joint position
  • joint velocity
  • contact force
  • terrain height
  • object pose

但真实机器人不一定都能稳定测到。

所以策略通常不应该直接依赖“真机拿不到”的完美信息。

这也是 Sim2Real 的第一条原则：

训练时给策略看的东西，尽量接近真机能提供的东西。

二、为什么机器人里 PPO 很常见

机器人强化学习里有很多算法：

  • PPO
  • SAC
  • TD3
  • DDPG
  • Dreamer 系列
  • model-based RL
  • offline RL

但在腿式机器人、仿真并行训练和工程 baseline 里，PPO 特别常见。

原因不是 PPO 永远最强，而是它在工程上有几个优势：

  • 稳定性较好
  • 对超参数不算特别敏感
  • 适合大规模并行采样
  • 和 GPU 仿真结合顺手
  • 实现相对清晰，容易做 baseline

2.1 PPO 的直觉

策略梯度的目标是让策略更倾向于产生高回报动作。

但如果每次更新太猛，策略可能突然崩掉。

PPO 的核心思想可以粗略理解为：

每次让策略往更好的方向走一点，但不要走太远。

  • advantage 大说明这个动作比预期好
  • entropy_bonus 用来鼓励探索，避免策略太早收缩

2.2 Actor 和 Critic

PPO 里通常有两个网络：

  • Actor：输出动作
  • Critic：估计当前状态或观测的价值

机器人任务中，Actor 真正会被部署。

Critic 主要用于训练阶段，帮助估计“当前局面有多好”。

训练时两个都用。

部署时通常只导出 Actor。

这点对工程部署很重要。你最后拿去上真机的不是整个训练框架，而是一个尽量小、稳定、延迟可控的策略网络。

三、机器人 RL 最难的不是算法，而是建环境

在机器人强化学习里，算法往往只占 20%。

剩下 80% 是：

  • 机器人模型是否正确
  • 观测是否合理
  • 动作空间是否稳定
  • 奖励函数是否诱导了正确行为
  • 仿真参数是否接近真实系统
  • 评估是否覆盖失败场景
  • 策略是否能部署

这也是为什么机器人 RL 文章不能只讲 PPO。

你真正要学的是“训练系统”。

3.1 观测设计

观测设计决定策略看见什么。

腿式机器人常见观测包括：

  • base angular velocity
  • projected gravity
  • commanded velocity
  • joint position
  • joint velocity
  • previous action
  • terrain height samples

机械臂操作任务常见观测包括：

  • end effector pose
  • joint state
  • object pose
  • gripper state
  • target pose
  • visual feature

观测设计的原则：

  • 不要给真机拿不到的信息
  • 不要遗漏完成任务必须的信息
  • 数值范围要归一化
  • 频率和延迟要接近部署环境

如果观测设计很差，再好的 PPO 也只是在错误输入上优化。

3.2 动作空间设计

动作可以有很多层级。

对腿式机器人来说，常见动作不是直接输出电机力矩，而是输出关节目标或残差：

这样做的好处是底层稳定性更强。

策略不用直接学习毫秒级力矩控制，而是在较高层输出动作。

对机械臂来说，动作可能是：

  • joint position delta
  • end effector pose delta
  • gripper command
  • impedance target
  • residual over classical controller

动作空间越底层，学习难度越高。

动作空间越高层，表达能力可能受限。

工程上要看任务，而不是盲目追求“端到端”。

每一项都要有工程含义：

  • 速度跟踪：希望机器人按指令走
  • 姿态稳定：不希望身体乱晃
  • 足端节律：希望形成合理步态
  • 能耗惩罚：不希望电机疯狂输出
  • 动作变化惩罚：不希望动作抖动
  • 碰撞惩罚：不希望膝盖、机身乱撞

奖励设计最常见的问题是 reward hacking。

也就是策略找到了“钻奖励空子”的方式。

例如：

  • 速度奖励给得太强，机器人用怪异姿态硬冲
  • 能耗惩罚太强，机器人学会不动
  • 姿态惩罚太强，机器人不敢探索
  • 终止条件太宽，策略学会摔倒前短暂拿高分

奖励不是一次写完的。

它更像是一个不断复盘的工程对象。

四、并行仿真为什么改变了机器人 RL

早期机器人 RL 很慢，一个环境一步一步跑，采样成本高。

现在机器人 RL 能快速迭代，很大程度上来自 GPU 并行仿真和批量环境。

假设一个环境每秒产生 1000 步数据。

如果你并行 4096 个环境，理论采样量会非常可观。

实际系统会受物理、渲染、通信和 GPU 调度限制，但思路是一样的：

这就是 Isaac Gym、legged_gym、Isaac Lab、MuJoCo Playground 这条线重要的原因。

4.1 legged_gym 的价值

legged_gym 是腿式机器人 RL 里非常经典的项目，很多四足和人形训练工程都受到它影响。

它的核心价值不是“界面漂亮”，而是给出了一个可复用的工程范式：

  • 并行环境
  • reward 配置
  • command 采样
  • terrain curriculum
  • domain randomization
  • policy export
  • rsl_rl 训练接口

如果你学腿式机器人 RL，legged_gym 值得读。

哪怕后来转到 Isaac Lab，也要理解它的设计思想。

4.2 rsl_rl 的价值

rsl_rl 是一个面向机器人学习的快速简洁 RL 实现。

在 legged_gym 一脉里，它常被用来训练 PPO。

学习 rsl_rl 的重点不是死记每个类名，而是理解训练脚本如何组织：

  • rollout storage
  • actor critic
  • advantage estimation
  • PPO update
  • logging
  • checkpoint

你能读懂这些，就能从“跑别人的命令”进到“改自己的任务”。

4.3 Isaac Lab 的价值

Isaac Lab 是 NVIDIA 当前主推的机器人学习框架，建立在 Isaac Sim 之上，面向强化学习、模仿学习和运动规划等工作流。

它的工程优势是：

  • 机器人模型和传感器生态更完整
  • 支持多类机器人任务
  • 和 Isaac Sim、USD、传感器仿真结合紧
  • 适合从仿真训练走向更完整的系统验证

如果目标是做机器人学习作品集，Isaac Lab 是 2026 年仍然非常值得跟踪的主线。

但它也更重。

机器配置、版本依赖、Isaac Sim 兼容性都要认真看。

4.4 MuJoCo Playground 和 Genesis

MuJoCo Playground 是 Google DeepMind 面向机器人学习和 Sim2Real 的开源环境集合，强调 GPU 加速、机器人学习和迁移。

Genesis 是 2024 末开源后快速受到关注的通用机器人与具身智能仿真框架，强调高速仿真和生成式世界方向。

这两类项目说明一个趋势：

机器人 RL 不再只是单个算法库，而是在向“仿真环境 + 数据生成 + 策略训练 + 迁移评估”的平台化方向发展。

对学习者来说，不要每个项目都深挖到底。

更实际的策略是：

  • 用 Stable-Baselines3 或 CleanRL 学算法结构
  • 用 legged_gym / rsl_rl 理解腿式 PPO 工程范式
  • 用 Isaac Lab 做作品集主线
  • 用 MuJoCo Playground / Genesis 观察前沿方向

五、开源项目矩阵

下面按学习阶段整理项目，而不是按热度罗列。

5.1 基础算法层

Stable-Baselines3 是 PyTorch 版本的可靠 RL 算法实现，适合快速搭 PPO、SAC、TD3 等 baseline。

适合用来做：

  • 理解 RL 算法接口
  • 快速训练经典控制环境
  • 对比 PPO 和 SAC
  • 做 logging、callback、checkpoint 入门

CleanRL 的特点是单文件实现，适合读源码。

它适合解决一个问题：

我到底想不想知道 PPO 内部每一步在干什么。

如果你只是想跑项目，用 SB3 更快。

如果你想理解算法细节，CleanRL 更适合读。

5.2 腿式训练层

这一层重点项目：

  • legged_gym
  • rsl_rl
  • Humanoid-Gym
  • Isaac Lab

腿式训练项目适合做作品集，因为结果直观：

  • 训练曲线
  • 步态视频
  • 不同地形评估
  • 随机推力恢复
  • 随机质量和摩擦测试
  • sim-to-real 分析报告

但也要注意：

腿式 RL 很容易变成“只跑通仓库 demo”。

想做得有含金量，至少要改一个变量：

  • 换地形
  • 改机器人模型
  • 改奖励项
  • 加随机化
  • 做对照实验
  • 写失败复盘

5.3 通用仿真和操作任务层

机械臂和操作任务可以关注：

  • ManiSkill
  • RoboMimic
  • Diffusion Policy
  • LeRobot

严格说 Diffusion Policy、RoboMimic、LeRobot 更偏模仿学习和数据驱动操作，不是本文的 PPO 主线。

但机器人学习项目经常会把 RL、IL、数据回放放在一起比较。

所以建议从一开始就知道这些工具的位置。

5.4 工程部署层

训练不是终点。

机器人项目最终要回到工程系统：

  • ROS 2
  • rosbag2
  • Foxglove
  • PlotJuggler
  • ONNX / TorchScript
  • controller interface
  • safety fallback

一个好项目应该能回答：

  • 策略输入来自哪里
  • 策略输出发给哪个控制器
  • 控制频率是多少
  • 延迟怎么测
  • 异常动作怎么拦截
  • 失败日志怎么复盘

这就是前一篇 ROS 2 文章和这一篇 RL 文章接上的地方。

六、Sim2Real：从仿真到真实机器人到底难在哪里

Sim2Real 不是一个单独技巧。

它是一组误差来源的管理。

仿真和真机之间至少有这些差异：

  • 质量和惯量不准
  • 摩擦系数不准
  • 电机响应不准
  • 关节间隙和背隙不准
  • 地形接触模型不准
  • 传感器噪声和延迟不准
  • 通信延迟不准
  • 电池电压和温升影响不准

所以策略在仿真里跑得很好，不代表能直接上真机。

6.1 域随机化

域随机化的思想是：

训练时不要让环境太完美，而是让策略见过一批合理扰动。

常见随机化包括：

  • mass randomization
  • friction randomization
  • motor strength randomization
  • latency randomization
  • terrain randomization
  • sensor noise randomization
  • push disturbance

直觉上可以理解为：

随机化不是越大越好。

太小，迁移不够鲁棒。

太大，训练任务变得过难，策略学不到好行为。

6.2 执行器模型

腿式机器人和人形机器人里，执行器模型特别关键。

仿真里如果电机像理想力矩源，策略会学到很激进的动作。

真实电机有：

  • 力矩上限
  • 速度上限
  • 电流限制
  • 控制延迟
  • 温度保护
  • 减速器摩擦
  • 通信周期

所以训练时要尽量让动作接口接近真实控制栈。

例如：

如果仿真动作接口和真机动作接口完全不同，Sim2Real 难度会明显上升。

6.3 延迟和频率

真实机器人一定有延迟。

包括：

  • 传感器采样延迟
  • 状态估计延迟
  • 策略推理延迟
  • 通信延迟
  • 控制器执行延迟

训练时如果完全没有延迟，策略可能学到依赖“即时反馈”的动作。

部署后就容易抖、慢半拍，甚至失稳。

七、一个机器人 RL 项目应该怎么做

八、评估指标：不要只看 reward

机器人 RL 里 reward 曲线很重要，但远远不够。

一个策略可能 reward 很高，但动作很丑、能耗很大、对扰动很脆。

建议至少记录这些指标：

  • task success rate
  • average episode return
  • tracking error
  • fall rate
  • energy usage
  • action smoothness
  • joint limit violation
  • collision count
  • recovery after push
  • performance under random seeds

九、常见失败模式

9.1 奖励很高，但动作很怪

原因通常是 reward hacking。

解决方向：

  • 看视频，不只看曲线
  • 分开记录每一项 reward
  • 增加姿态、能耗、动作变化惩罚
  • 检查终止条件
  • 做不同随机种子评估

9.2 训练不收敛

可能原因：

  • reward 太稀疏
  • 动作尺度不合理
  • 观测没有归一化
  • learning rate 太大
  • episode 太短或终止过早
  • 并行环境配置错误

先不要急着换算法。

大部分时候是环境和奖励问题。

9.3 仿真里很好，随机化后一塌糊涂

说明策略对某些物理参数很敏感。

排查方式：

  • 一次只随机化一个参数
  • 记录每种扰动下的成功率
  • 看是摩擦、质量、延迟还是电机限制导致退化
  • 对关键参数做 curriculum

9.4 训练视频很好，但部署接口接不上

这是最常见的工程断裂。

原因可能是：

  • 训练动作是 joint target，真机接口需要 torque
  • 训练观测包含仿真内部状态，真机没有
  • 训练频率和部署频率不同
  • 坐标系不一致
  • action scale 没统一
  • safety limit 没处理

所以从一开始就要设计部署接口，而不是训练完再想怎么接。

9.5 不同随机种子结果差很多

这说明策略稳定性不够。

可以做：

  • 多 seed 训练
  • 记录均值和方差
  • 调整 reward 权重
  • 降低 learning rate
  • 增加训练步数
  • 增加环境多样性

如果一篇项目报告只展示最好的一次结果，说服力会弱。

十、2026 年值得关注的前沿方向

截至 2026 年 5 月，机器人强化学习和机器人学习生态有几个明显趋势。

10.1 Isaac Lab 成为工程主线之一

Isaac Lab 的定位已经不只是一个训练 demo 集合，而是面向机器人学习工作流的统一框架。

它把强化学习、模仿学习、运动规划、传感器仿真、机器人模型和 Isaac Sim 生态接到一起。

对作品集来说，它适合做“中大型机器人学习项目”的主线。

10.2 MuJoCo 生态重新活跃

MuJoCo Playground 说明 MuJoCo 生态也在向 GPU 加速、机器人学习和 Sim2Real 工作流发展。

如果你更喜欢轻量、可控、物理清晰的环境，MuJoCo 仍然值得长期关注。

10.3 Genesis 带来高速仿真和生成式世界想象

Genesis 的关注点不只是传统物理仿真，还带有生成式世界和通用机器人学习的味道。

它还在快速演进，学习时要保持判断：

  • 看它适合哪些任务
  • 看接口是否稳定
  • 看示例是否可复现
  • 不要只因为新就盲目迁移

10.4 RL 和模仿学习会越来越混合

很多真实机器人任务不会只靠 RL。

未来常见组合可能是：

也就是：

  • 用示教解决探索难
  • 用 RL 提升鲁棒性
  • 用真机数据修正仿真偏差
  • 用安全控制器兜底

10.5 评估和复盘会比单纯训练更重要

机器人学习越接近真实系统，越需要工程复盘。

你需要证明：

  • 策略在哪些场景有效
  • 哪些扰动会失败
  • 为什么失败
  • 如何记录失败
  • 如何下一轮改进

这也是为什么 rosbag2、Foxglove、PlotJuggler 这些工具会和 RL 项目同时出现。

十一、学习顺序建议

如果你从零开始，不建议直接冲 Isaac Lab 人形。

更稳的顺序是：

  1. 用 Stable-Baselines3 跑 PPO baseline
  2. 用 CleanRL 读一遍 PPO 单文件实现
  3. 理解 observation、action、reward、done 的环境接口
  4. 跑通 legged_gym 或 Isaac Lab 的一个 locomotion demo
  5. 改一个 reward 项，观察策略变化
  6. 做一组 domain randomization 对照实验
  7. 导出策略，做独立评估视频
  8. 写一份失败复盘报告
  9. 进阶再接 ROS 2 推理节点或真机接口

每一步都要有可观察产物。

学习机器人 RL，最怕只留下几行命令。

最有价值的是留下：

  • 训练曲线
  • 评估视频
  • 配置文件
  • 版本记录
  • reward 分项图
  • 随机种子对照
  • 失败案例
  • 复盘文档

这些东西比“我看懂 PPO 了”更能证明能力。

十二、这篇的核心结论

机器人强化学习不是“选一个算法然后训练”。

它是一条完整工程链路：

这篇最重要的结论有六个：

  1. PPO 常见，是因为稳定、适合并行采样、工程实现成熟。
  2. 机器人 RL 的难点更多在环境、奖励、动作接口和评估，而不是算法名字。
  3. legged_gym 和 rsl_rl 值得学习，因为它们体现了腿式机器人 RL 的经典工程范式。
  4. Isaac Lab 是当前机器人学习作品集非常值得跟踪的主线之一。
  5. Sim2Real 的关键不是玄学，而是质量、摩擦、执行器、延迟、传感器噪声等误差管理。
  6. 能写进履历的项目必须有训练曲线、评估视频、对照实验和失败复盘。
