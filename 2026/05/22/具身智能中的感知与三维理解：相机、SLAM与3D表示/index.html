具身智能中的感知与三维理解：相机、SLAM 与 3D 表示

前面几篇文章已经把机器人系统里的基础链路铺开了：

  • 数学基础
  • 坐标系与姿态表示
  • 运动学
  • 概率、滤波与状态估计

这些内容主要回答的是：

机器人怎样描述自己，怎样估计自己，怎样把目标变成动作。

但一台真实机器人不能只知道“自己在哪里”。它还必须回答另一个同样关键的问题：

世界里有什么，它们在哪里，我能不能靠近、抓取、绕开或操作它们。

这就是感知与三维理解进入具身智能系统的入口。

它接在概率与滤波之后，和后面的机械臂控制、接触抓取、四足控制、人形控制都直接相连。读完这一篇，你应该能理解机器人感知链路如何从传感器数据出发，经过标定、定位、建图、语义理解，最后变成规划器和控制器能使用的任务目标。

一、机器人感知到底在解决什么问题

很多人第一次接触机器人感知，会把它理解成：

用相机识别物体。

这当然是感知的一部分，但远远不够。

对真正的机器人系统来说，感知至少要回答五类问题。

1.1 我在哪里

这对应定位问题。

例如：

  • 移动机器人在房间里的位置
  • 四足机器人在地图里的位姿
  • 无人机在空间中的姿态和速度
  • 人形机器人骨盆相对世界坐标系的位置

这一类问题通常和 SLAM、VIO、LIO、状态估计强相关。

1.2 周围环境长什么样

这对应建图和三维表示问题。

机器人需要知道：

  • 地面在哪里
  • 墙在哪里
  • 桌子在哪里
  • 障碍物在哪里
  • 哪些空间可以通过
  • 哪些区域可以放脚或放置物体

这时只看 2D 图片不够，通常要进入点云、深度图、体素地图、TSDF、mesh 或神经三维表示。

1.3 目标物体在哪里

这对应检测、分割和 6D 位姿估计。

机器人不是只要知道“图像里有杯子”，而是要知道：

  • 杯子在相机坐标系下的位置
  • 杯子在机械臂底座坐标系下的位置
  • 杯子的大致姿态
  • 杯口朝向
  • 抓取点在哪里

这就要求视觉模型的输出必须进入机器人坐标链。

1.4 哪些东西可以交互

具身智能关注的是行动，不只是识别。

所以机器人还要判断：

  • 这个物体能不能抓
  • 这个抽屉能不能拉
  • 这个门把手能不能转
  • 这块地能不能踩
  • 这个区域能不能通过

这部分会逐渐连接到 affordance、开放词汇感知、VLA 模型和机器人学习。

1.5 感知结果能不能被控制器使用

这是最容易被忽略的一点。

视觉模型输出一个框，没有什么用。

点云里分割出一团点，也还不够。

二、感知链路的总结构

一条机器人感知链路通常可以分成六段：

  1. 传感器输入
  2. 标定与时间同步
  3. 定位与建图
  4. 三维表示
  5. 语义理解
  6. 任务输出

这六段不是孤立模块，而是一条闭环。

如果只看单点算法，很容易误判问题。

比如机械臂抓不准，可能不是抓取算法错了，而是：

  • 相机外参偏了
  • 深度图有洞
  • 目标分割不稳定
  • 坐标变换顺序错了
  • 机械臂底座坐标系和相机坐标系没对齐
  • 物体 6D 位姿估计跳变

所以做机器人感知时，一定要建立系统视角。

三、传感器：相机、RGB-D、LiDAR 和 IMU

机器人感知不是只有相机。

不同传感器提供的信息不同，失效方式也不同。

3.1 普通相机

普通 RGB 相机提供颜色和纹理。

它适合：

  • 目标检测
  • 图像分割
  • 物体识别
  • 语义理解
  • VLA 模型输入

但单目相机有一个天然问题：

深度不直接可观测。

单张图片里看到一个杯子，你知道它在画面里的位置，但不能直接知道它离机器人到底多远。

所以单目感知往往需要：

  • 多帧运动估计
  • 双目匹配
  • 深度网络
  • 结合 IMU 或先验尺寸

3.2 双目相机

双目相机通过左右视差估计深度。

优点是：

  • 成本相对低
  • 能直接估计深度
  • 适合 VIO 和稠密深度

缺点是：

  • 弱纹理区域深度不稳
  • 远距离深度误差变大
  • 标定质量非常关键
  • 光照变化会影响匹配

双目系统看起来简单，但真正工程落地时，标定、同步和曝光控制都很要命。

3.3 RGB-D 相机

RGB-D 相机直接输出彩色图和深度图。

它适合：

  • 桌面抓取
  • 室内建图
  • 点云处理
  • 物体分割后转三维点云

常见问题包括：

  • 反光物体深度缺失
  • 黑色物体深度不稳
  • 透明物体经常测不准
  • 强光下红外深度可能失效
  • 深度图边缘会有噪声

所以 RGB-D 适合入门，但不要误以为“有深度相机就解决了三维理解”。

3.4 LiDAR

LiDAR 提供稳定的几何距离信息。

它适合：

  • 移动机器人导航
  • 室外建图
  • 四足巡检
  • 无人车和无人机定位
  • LIO 系统

LiDAR 的优势是几何稳定，缺点是语义弱。

它告诉你“这里有一片点”，但不直接告诉你“这是一把椅子”。

3.5 IMU

IMU 在感知系统里不是用来看物体，而是用来补运动状态。

它提供：

  • 角速度
  • 线加速度
  • 姿态变化趋势
  • 高频运动先验

在 VIO 和 LIO 里，IMU 常常承担一个关键角色：

在相机或 LiDAR 两帧之间，提供高频运动补偿。

但 IMU 会漂，所以必须和视觉、LiDAR、编码器或接触约束融合。

四、标定与同步：感知系统最容易被低估的部分

很多感知问题，不是算法不够高级，而是标定和同步没做好。

4.1 内参标定

相机内参描述相机自己的成像模型。

常见参数包括：

  • 焦距
  • 主点
  • 畸变系数

如果内参不准，图像点反投影到三维空间时就会偏。

这会导致：

  • 深度恢复不准
  • 双目匹配误差
  • 视觉里程计漂移
  • 6D 位姿估计偏差

4.2 外参标定

外参描述两个坐标系之间的关系。

例如：

机器人里最常见的外参问题是：

视觉看见了目标，但机械臂伸过去抓偏。

这往往不是模型没识别出来，而是相机坐标系到机械臂底座坐标系的变换不准。

4.3 手眼标定

机械臂场景里，手眼标定尤其重要。

常见两种结构：

  • eye-in-hand：相机装在机械臂末端
  • eye-to-hand：相机固定在外部

两者的问题不同。

eye-in-hand 适合近距离观察，但相机一直跟着手动，图像会变化。

eye-to-hand 视野稳定，但外参必须非常准，否则抓取点会整体偏移。

4.4 时间同步

时间同步比很多人想象得更重要。

如果相机、IMU、LiDAR 的时间戳对不上，系统会把不同时刻的状态硬拼在一起。

结果可能是：

  • VIO 轨迹抖动
  • LiDAR 点云扭曲
  • 快速运动时定位发散
  • 控制器接收到过期目标

所以做感知系统时，不要只问“传感器精度是多少”，还要问：

数据到底是不是同一时刻的。

4.5 推荐开源项目

这一层最值得练的项目包括：

  • OpenCV：相机标定、图像处理基础库。
  • Kalibr：相机、IMU 标定工具。
  • AprilTag：标定板、定位和机器人视觉常用工具。

最小实践可以这样做：

  1. 用 OpenCV 标定一台相机。
  2. 用 AprilTag 做一个固定标定板。
  3. 如果有 IMU，用 Kalibr 做相机-IMU 标定。
  4. 把标定结果写入 ROS 2 参数或配置文件。
  5. 可视化外参变换，确认坐标轴方向没有反。

履历表达可以写成：

  • 完成相机内参、相机-IMU 外参与手眼标定流程，并将标定结果接入 ROS 2 TF 链。
  • 使用 AprilTag / Kalibr 评估标定误差，定位机械臂抓取偏移中的外参问题。

五、SLAM、VIO 和 LIO：机器人怎样知道自己在哪

SLAM 的全称是 Simultaneous Localization and Mapping。

它同时做两件事：

  1. 定位自己
  2. 建立环境地图

但在机器人系统里，SLAM 不是一个单一算法，而是一类系统。

5.1 视觉 SLAM

视觉 SLAM 主要用相机图像估计运动和地图。

典型路线包括：

  • 特征点法
  • 直接法
  • 半直接法
  • 语义辅助 SLAM

代表项目是 ORB-SLAM3。

ORB-SLAM3 的价值不只是“能跑”，而是它把单目、双目、RGB-D、视觉惯性等模式组织成一个完整系统，非常适合用来理解视觉 SLAM 的工程结构。

5.2 VIO

VIO 是 Visual-Inertial Odometry。

它融合相机和 IMU。

相机提供环境约束，IMU 提供高频运动先验。

典型项目是 VINS-Fusion。

VIO 常用于：

  • 无人机
  • AR / VR
  • 手持设备
  • 小型移动机器人

VIO 的难点是：

  • 相机-IMU 外参
  • 时间偏移
  • IMU bias
  • 快速运动模糊
  • 特征点退化

如果 VIO 跑飞，不要先怪算法。先看标定、时间戳、曝光、运动模糊和特征质量。

5.3 LIO

LIO 是 LiDAR-Inertial Odometry。

它融合 LiDAR 和 IMU。

典型项目包括：

  • FAST-LIO2
  • LIO-SAM

LIO 在室外、巡检、四足机器人和无人车里很常见。

它的优势是几何稳定，尤其在纹理少的环境里比纯视觉更可靠。

但它也有问题：

  • 动态物体会污染点云
  • 雨雾粉尘会影响激光
  • 点云配准依赖环境几何结构
  • 地面、走廊等重复结构会带来退化

5.4 SLAM 输出怎样接到机器人系统

SLAM 输出通常不是最终任务目标，而是系统状态的一部分。

它常常会进入：

  • TF 坐标链
  • 状态估计节点
  • 导航地图
  • 局部规划器
  • 数据记录与回放系统

一个常见结构是：

如果 SLAM 坐标系、机器人 base 坐标系和地图坐标系没有管理好，后面所有规划和控制都会出问题。

5.5 最小实践项目

建议这样做：

  1. 下载一个公开数据集或 rosbag。
  2. 跑 ORB-SLAM3 或 VINS-Fusion。
  3. 用 evo 评估轨迹误差。
  4. 改变相机频率、IMU 噪声或外参，观察轨迹变化。
  5. 把 SLAM 输出接到 ROS 2 TF 树里。

履历表达可以写成：

  • 复现 ORB-SLAM3 / VINS-Fusion，在公开数据集上完成轨迹评估，并用 evo 分析 ATE/RPE。
  • 将 SLAM 输出接入 ROS 2 TF 链，为导航与机械臂任务提供世界坐标系下的位姿输入。

六、三维表示：点云、深度图、体素和神经表示

机器人要和世界交互，最终必须进入三维。

二维图像告诉你“画面里有什么”，三维表示告诉你：

这个东西在空间里的哪里。

6.1 深度图

深度图是最直接的三维入口。

每个像素对应一个深度值。

它的优点是和图像天然对齐，适合从分割 mask 转成三维点。

6.2 点云

点云是机器人三维理解里最常见的数据结构。

它由大量三维点组成：

有时还会带：

  • 颜色
  • 法向量
  • 强度
  • 语义标签

点云适合：

  • 平面分割
  • 物体聚类
  • 障碍物检测
  • 抓取点估计
  • 地形建模

推荐项目是 Open3D。

Open3D 的优点是接口清晰，适合快速做点云处理、可视化、配准和重建。

6.3 TSDF 和体素地图

TSDF 常用于将多帧深度融合成稳定三维模型。

它的核心思路是：把空间划成体素，再记录每个体素到表面的距离关系。

它适合：

  • 室内重建
  • 桌面场景融合
  • 机器人工作空间建模
  • 碰撞检测前的几何建图

6.4 Mesh

Mesh 比点云更接近物体表面。

它包含：

  • 顶点
  • 边
  • 面

Mesh 适合可视化、仿真和碰撞模型，但生成稳定 mesh 通常比处理点云更难。

6.5 NeRF、3D Gaussian Splatting 与机器人

近几年三维重建里最火的方向包括：

  • NeRF
  • 3D Gaussian Splatting
  • 神经场表示

相关开源项目包括：

  • nerfstudio
  • gsplat
  • COLMAP

这些技术在视觉效果上很强，但用于机器人时要特别注意：

  • 能不能实时更新
  • 能不能输出可碰撞几何
  • 能不能提供尺度一致的坐标
  • 能不能接入规划器
  • 动态物体如何处理

也就是说，机器人不只是要“看起来真实”的三维重建，而是要“能被规划和控制使用”的三维表示。

七、语义理解：检测、分割、开放词汇和 6D 位姿

三维几何告诉机器人“哪里有东西”。

语义理解告诉机器人：

那是什么东西。

7.1 目标检测

目标检测输出 bounding box。

它适合快速知道图像里有哪些目标。

但对机器人来说，box 只是第一步。

因为抓取和导航通常还需要：

  • 三维位置
  • 物体轮廓
  • 姿态
  • 可抓区域
  • 可通行空间

7.2 图像分割

分割比检测更适合机器人。

因为分割能告诉你目标的像素区域。

有了 mask，就可以结合深度图得到目标点云：

这对桌面抓取、物体操作非常有用。

这类能力对具身智能很重要，因为机器人任务往往不是固定类别，而是开放环境里的语言指令。

7.4 6D 位姿估计

6D 位姿估计回答的是：

物体在三维空间中的位置和姿态是什么。

它通常包含：

  • 3D position
  • 3D orientation

对机械臂抓取、插接、装配任务来说，6D 位姿比 2D 检测框重要得多。

例如：

  • 杯子把手朝哪边
  • 螺丝孔法向量朝哪里
  • 工具柄的方向是什么
  • 物体是否倾斜

这些都会直接影响抓取和操作策略。

八、开源项目矩阵：每一类项目解决什么问题

感知方向的开源项目很多，不建议一上来全都碰。

更好的方式是按目标分组。

  • ORB-SLAM3

  • 轨迹估计
  • 定位建图

  • SLAM pipeline

8.2 三维重建与点云

8.4 开放词汇感知

  • 视觉输出到三维点云

履历关键词：

  • visual grounding
  • segmentation
  • language-conditioned detection

九、最推荐做的三个项目

如果时间有限，不要从十几个开源项目里乱试。

可以先做下面三个。

9.1 项目一：RGB-D 物体点云提取

目标：

从一张 RGB-D 图里，提取目标物体的三维点云。

技术链路：

最小实现：

  1. 读取 RGB 图和深度图。
  2. 用 SAM 2 或 Grounding DINO 得到目标 mask。
  3. 根据相机内参把 mask 区域反投影成点云。
  4. 用 Open3D 去除离群点。
  5. 计算物体中心点和包围盒。

履历表达：

  • 构建 RGB-D 目标点云提取 pipeline，结合开放词汇分割和 Open3D 点云处理，输出机器人可用的目标三维位置。

9.2 项目二：SLAM 轨迹评估与误差分析

目标：

跑通一个 SLAM 系统，并能解释轨迹为什么漂。

技术链路：

最小实现：

  1. 下载公开数据集。
  2. 跑 ORB-SLAM3 或 VINS-Fusion。
  3. 导出轨迹。
  4. 用 evo 计算 ATE/RPE。
  5. 改动相机参数或 IMU 噪声，比较误差变化。

履历表达：

  • 复现视觉 SLAM / VIO 系统，完成轨迹误差评估和参数敏感性分析，定位特征退化、时间同步和外参误差对结果的影响。

9.3 项目三：视觉到机械臂抓取目标

目标：

把感知结果转成机械臂底座坐标系下的抓取候选。

技术链路：

最小实现：

  1. 在桌面放一个目标物体。
  2. 用 RGB-D 相机得到目标点云。
  3. 标定相机和机械臂底座外参。
  4. 输出 target_pose_in_base。
  5. 用 MoveIt 2 规划机械臂末端到目标附近。

履历表达：

  • 搭建视觉到机械臂抓取目标的最小闭环，实现目标分割、点云提取、外参变换和 MoveIt 2 规划输入。

这个项目非常适合放进简历，因为它把感知、坐标系、运动学和规划串起来了。

十、前沿动态：2026-05 时点应该关注什么

感知与三维理解变化很快，尤其是大模型进入机器人之后，很多传统模块正在被重新组合。

下面是当前值得跟踪的方向。

10.1 开放词汇感知正在变成机器人入口

传统机器人视觉常常依赖固定类别。

现在更重要的是：

机器人能不能根据语言找到目标。

例如：

这会把 SAM 2、Grounding DINO、CLIP、VLM 和 VLA 模型接到机器人任务层。

但要注意：开放词汇模型本身并不等于机器人智能。

它还必须接：

  • 深度
  • 坐标变换
  • 规划
  • 控制
  • 失败检测

10.2 三维表示正在从点云走向可学习场景

NeRF、3D Gaussian Splatting、神经场这类方法让三维重建效果变得很强。

但机器人真正关心的是：

  • 能不能实时
  • 能不能更新
  • 能不能规划
  • 能不能处理动态物体
  • 能不能输出碰撞几何

所以未来的重点不是“重建图好不好看”，而是：

三维表示能不能支撑机器人行动。

10.3 SLAM 不会消失，但会和语义、学习更紧密

即使 VLA 模型很火，机器人依然需要稳定定位和地图。

原因很简单：

  • 控制器需要坐标
  • 导航需要地图
  • 抓取需要目标位姿
  • 长程任务需要空间记忆

所以 SLAM 不会被视觉大模型直接替代。

10.4 感知评估会越来越重要

机器人感知不是只看 mAP。

真实系统更关心：

  • 目标位姿误差
  • 抓取成功率
  • 导航失败率
  • 延迟
  • 稳定性
  • 长时间运行漂移
  • 数据闭环后的改进幅度

所以做项目时，最好不要只展示“识别成功截图”，而要写清楚：

这个感知结果接到机器人系统后，任务成功率有没有提高。

十一、常见失效模式

感知系统最麻烦的地方是：问题常常不是单点错误，而是链路误差叠加。

11.1 相机看到了，但机器人抓偏

常见原因：

  • 外参不准
  • 深度图边缘噪声
  • 物体 mask 不稳定
  • 坐标系方向写反
  • 机械臂末端工具坐标没标好

排查顺序：

  1. 固定目标物体。
  2. 打印相机坐标系下的目标点。
  3. 可视化 base 坐标系下的目标点。
  4. 用机械臂低速移动到目标上方。
  5. 检查偏差是否固定方向。

如果偏差总是固定方向，多半是外参问题。

如果偏差随机跳，多半是感知或深度噪声问题。

11.2 SLAM 轨迹突然飞掉

常见原因：

  • 特征点太少
  • 快速运动模糊
  • IMU 时间戳不准
  • 外参错误
  • 场景重复纹理
  • 回环检测误匹配

排查顺序：

  1. 看图像质量。
  2. 看特征点数量。
  3. 看 IMU 是否饱和。
  4. 看时间戳是否单调。
  5. 用 evo 对比误差。

11.3 点云看起来像“重影”

常见原因：

  • 时间同步问题
  • 位姿估计延迟
  • 深度相机运动太快
  • LiDAR 去畸变没做好
  • 多帧融合时外参错了

这类问题一旦出现，后面的分割、抓取和规划都会被污染。

11.4 开放词汇模型找到目标，但机器人还是失败

常见原因：

  • 找到的是 2D 区域，不是 3D 位姿
  • 目标被遮挡
  • 分割 mask 包含背景
  • 深度缺失
  • 抓取点不可达
  • 规划器无法绕过障碍物

所以开放词汇感知一定要接三维和规划，不能停在图片结果。

十二、这一篇的核心结论

机器人感知不是“识别图片”，而是把真实世界转换成机器人可执行的任务输入。

一条完整链路通常是：

这一篇最重要的结论有五个：

  1. 传感器各有失效模式，不存在万能相机。
  2. 标定和时间同步是感知系统的地基。
  3. SLAM / VIO / LIO 解决的是定位与建图，不是最终任务。
  4. 三维表示必须能被规划和控制使用，不能只追求视觉效果。
  5. 开放词汇感知很重要，但必须接入深度、坐标系、规划和控制。

如果你想把这一层做成有履历价值的项目，优先选下面三条：

  • RGB-D 目标点云提取
  • SLAM 轨迹评估与误差分析
  • 视觉到机械臂抓取目标闭环

能把这三条跑通，你对“机器人怎样看世界”就不再停留在概念层了。
